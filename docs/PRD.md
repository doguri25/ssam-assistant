## 1. 개요

### 1.1 한 줄 소개
평가·연수·계획·학급·품의 업무를 왼쪽 세로 메뉴 하나에 모으고, AI가 초안을 쓰면 교사는 확인·수정만 하는 Windows 앱(웹판 포함).

### 1.2 풀려는 문제 (기획서 요약)
- 같은 날짜와 정보를 여러 곳에 반복해서 옮겨 적고, 서류와 실제 업무가 따로 논다.
- 평가: 평어를 학생마다 쓰고 나이스에 하나씩 붙여넣느라 늦게까지 남는다.
- 계획: 매년 작년 계획서에서 연도·날짜만 바꾸고, 작년 결과의 개선점은 빠진다.
- 행사: 계획서·역할 분담표·가정통신문·결과 보고서를 매번 따로 만든다.
- 품의: 회계가 낯선 교사가 에듀파인 품의를 쓰기 어렵다.
- 연수: 이수증을 메신저로 받고 엑셀에 한 명씩 체크한다.

### 1.3 대회 버전의 목표와 성공 기준
1. 심사위원이 설치 파일 또는 웹 주소로 앱을 열어, 아래 네 흐름을 예시 자료로 처음부터 끝까지 따라 할 수 있다.
   - 평가: 평가계획을 넣고 교과 평어 만들기 (기존 기능)
   - 품의: 메모와 견적서로 에듀파인 붙여넣기용 초안 만들기
   - 행사계획: 구성안 → 문서 세트(.hwpx) → 설문 QR → 결과 보고서
   - 연간계획: 작년 자료와 지침으로 개선된 계획서 초안(.hwpx)과 월별 일정 만들기
   - 학급운영계획: 작년 학급운영계획 목차 그대로 올해 초안, 진도표·평가계획 첨부를 표로(.hwpx)
2. 연수·학급은 화면 시안으로 앱의 전체 그림을 보여 준다.
3. AI는 Claude·Gemini·GPT·업스테이지 중 하나의 키로 동작한다.
4. 2026-11-08까지 1.0.0 릴리즈(설치 파일·실행 파일)와 웹판을 공개 레포에 올린다.

## 2. 사용자

| 사용자 | 대회 버전에서 쓰는 곳 |
|---|---|
| 학급 담임 교사 | 평가(교과 평어·창체·행특·평가지 채점·단원평가), 학급운영계획, 학급, 품의 |
| 업무 담당 교사 | 연간계획, 행사계획, 품의, 연수 현황판(시안) |
| 모든 교직원 | 내 필수연수(시안) |

로그인과 권한 구분은 대회 버전에 없다(서버가 없으므로). 모든 기능을 한 사람이 자기 컴퓨터에서 쓴다.

## 3. 범위

### 3.1 대회 버전에서 동작하는 것
- 평가: 평어 만들기 1.8.0의 기능 전부 (교과 평어, 창의적 체험활동, 행동특성 및 종합의견, 평가지 채점, 나이스 자동 입력) + 단원평가(자동채점·학생 피드백·결과 쌓기, 설계: `docs/superpowers/specs/2026-10-29-unit-test-design.md`)
- 품의: 새 품의, 저장한 템플릿, 최근 작성
- 계획: 연간계획, 행사계획, 학급운영계획(설계: `docs/superpowers/specs/2026-10-29-class-plan-design.md`)
- 학급: 오늘 수업, 진도표·시수, 주간학습안내 (선생님 결정으로 시안에서 동작으로 바꿈, 설계: `docs/superpowers/specs/2026-10-29-class-menu-design.md`)
- 설정: 학급 명단(엑셀·CSV 가져오기), AI, 화면(테마), 학교 정보, 학년도(백업·오가기), 품의 기준
- Windows 설치판·실행 파일판, 자동 업데이트, 프로그램 삭제, 웹판

### 3.2 화면 시안만 두는 것
- 연수: 내 필수연수, 연수 현황판

시안은 예시 자료로 채운 실제 화면이다. 맨 위에 「대회 이후 제공 예정 · 미리보기」 띠를 두고, 버튼을 누르면 「준비 중이에요」라고 알린다.

### 3.3 범위 밖 (대회 이후)
- 학교 공용 서버, 로그인, 권한, 교직원 간 자료 공유
- 학사일정을 모든 담임의 진도표에 자동 반영
- 연수 알림 발송, 이수증 자동 인식
- 평어 만들기 앱의 자료를 쌤비서로 가져오기
- 학교 양식(.hwpx)의 빈칸에 내용 채워 넣기

## 4. 화면 구성

### 4.1 창 틀
- **왼쪽 세로 메뉴**: 위에서부터 로고(마크 42px + 「쌤비서」 22px) → 평가 · 연수 · 계획 · 학급 · 품의 → (아래쪽) 사용 중인 AI 표시 → 설정.
- **상단 헤더**: 메뉴 제목(예: 「품의」) + 가로 하위 메뉴 + 오른쪽 주요 버튼. 배경색 없이 아래 선 하나로만 구분한다.
- **┌ 모양 정렬**: 로고 칸과 헤더의 높이를 76px로 맞춰, 로고 칸 아래 선과 헤더 아래 선이 한 줄로 이어진다.
- 지금 보고 있는 하위 메뉴는 헤더 아래 선에 닿는 밑줄로 표시한다.
- **본문**: 최대 너비 1120px, 가운데 정렬. 맨 위에 쪽 제목·설명과 쪽 안의 선택(예: 품의 종류), 그 아래 입력 칸과 결과 칸을 같은 너비·같은 높이로 나란히 둔다.
- **좁은 화면**(태블릿·휴대폰 웹): 세로 메뉴가 위로 올라가고, 두 칸은 위아래로 쌓인다.
- 헤더 맨 오른쪽에 ⋮ 메뉴(업데이트 확인·프로그램 삭제)를 둔다. 동작은 평어 만들기와 같다.

### 4.2 메뉴와 하위 메뉴

| 메뉴 | 하위 메뉴(가로) | 대회 버전 |
|---|---|---|
| 평가 | 교과 평어 · 창의적 체험활동 · 행동특성 · 평가지 채점 · 단원평가 | 동작 |
| 연수 | 내 필수연수 · 연수 현황판 | 시안 |
| 계획 | 연간계획 · 행사계획 · 학급운영계획 | 동작 |
| 학급 | 오늘 수업 · 진도표·시수 · 주간학습안내 | 동작 |
| 품의 | 새 품의 · 저장한 템플릿 · 최근 작성 | 동작 |
| 설정 | 학급 명단 · AI · 화면 · 학교 정보 · 학년도 · 품의 기준 | 동작 |

앱을 켜면 마지막으로 보던 메뉴와 하위 메뉴를 연다. 처음이면 평가 › 교과 평어.

### 4.3 테마
설정 › 화면에서 고른다. 미리보기 카드 5개 중 하나를 누르면 바로 바뀌고, 이 컴퓨터에 저장된다.

| 테마 | 세로 메뉴 | 바탕 | 포인트 색 | 글꼴 | 느낌 |
|---|---|---|---|---|---|
| 다크 내비 (기본) | #15171c | #f5f6f8 | #4f46e5 | Gothic A1 | 어두운 세로 메뉴, 밝은 작업 영역 |
| 모노 라인 | #ffffff + 선 | #fafafa | #111111 | IBM Plex Sans KR | 흰 바탕에 가는 선과 검정 하나 |
| 소프트 카드 | #ffffff + 선 | #f2f4f6 | #2563eb | Noto Sans KR | 둥근 카드와 큼직한 버튼 |
| 종이 문서 | #efebe2 | #f7f5f0 | #1f3a5f | Noto Sans KR + Noto Serif KR(제목) | 종이색 바탕, 명조 제목 |
| 아이콘 레일 | #eef3f2, 폭 96px | #ffffff | #0f766e | Noto Sans KR | 아이콘+짧은 글자 메뉴, 넓은 작업 영역 |

- 화면 코드는 색 이름이 아니라 `--frame`, `--page`, `--accent` 같은 테마 값만 쓴다. 테마는 `<html data-theme="…">` 하나로 바뀐다. 평가 화면도 같은 값을 따른다.
- 모든 글자는 바탕과 대비 4.5:1 이상, 누르는 곳은 44px 이상.
- 글꼴은 Google Fonts에서 불러온다. 한글 글꼴을 앱에 넣으면 설치 파일이 수십 MB로 커지므로 넣지 않고, 인터넷이 없으면 Windows 기본 글꼴(맑은 고딕)로 보이게 한다.

## 5. 기능 요구사항

요구사항 번호: 평가 E, 품의 P, 연간계획 Y, 행사계획 V, 학급운영계획 K, 연수 T, 학급 C, 설정 S, 떠 있는 버튼 I.
**원칙: AI는 문장만 쓴다. 금액 계산, 빈칸 검사, 날짜 겹침, 개인정보 검사는 앱이 직접 한다.**

### 5.1 평가 (기존 기능 유지)
- E-1 평어 만들기 1.8.0의 네 탭(교과 평어, 창의적 체험활동, 행동특성 및 종합의견, 평가지 채점)을 하위 메뉴로 옮긴다. 기능과 문장 규칙(끝맺음 '~함.', 대명사, 분량·바이트, 사용함 표시, 학습지·평가지 읽기, 이름 칸 가리기)은 바꾸지 않는다.
- E-2 학급 명단(학생 수·예외 번호)과 학년은 설정 › 학급 명단에서 읽는다. 창체·행특·평가지 채점이 같이 쓴다.
- E-4 문서 내보내기(core/doc-export.js): 한글 파일을 내보내던 곳(연간계획·행사계획 문서 세트와 결과 보고서·학급운영계획·주간학습안내·단원평가 결과지와 성적 일람표)은 [○○로 내려받기][▾] 나뉜 단추. ▾에서 한글(.hwpx)·워드(.docx)·PDF(A4 인쇄 모양을 인쇄 창으로 띄워 「PDF로 저장」)를 고르면 바로 그 형식으로 내보내고, 고른 형식은 학년도와 상관없이 기억해 모든 메뉴의 기본으로 쓴다(처음엔 한글). 품의는 담당 선생님이 같은 모듈로 붙인다.
- E-3 적힌 번호로 학생 맞추기(평가지 채점·단원평가 공통, core/student-no.js): 켜면 [번호 칸 정하기]로 학생이 번호를 쓰는 칸을 한 번 표시한다. 채점 전에 학생마다 첫 쪽의 번호 칸만 잘라(이름 칸이 겹치면 하얗게) 20명씩 그림 한 장으로 모아 AI가 읽고, 확인 표에서 못 읽음·겹침·명단 밖 번호를 노란 줄로 보여 다 고쳐야 채점한다. 확인하면 학생과 그 쪽을 함께 번호 차례로 늘어놓는다. 한 학생의 쪽은 붙어 있다고 본다(학생 한 명 ○쪽).
- E-3 AI 부르기는 공통 AI 모듈(9장)을 쓴다. 평가 전용 설정(끝맺음 '~함/~한다', 평어 길이 등)은 평가 화면 안의 「평어 쓰는 방식」에 둔다.
- E-4 나이스 자동 입력(전체복사 → Ctrl+V로 학생 칸에 차례로 넣기)은 Windows 앱에서 그대로 동작한다.
- E-5 평가지 채점·창체 학습지 읽기에서 업스테이지를 쓰고 있으면 「손글씨 이미지는 Claude·Gemini·GPT를 권장해요」라고 안내한다(쓰는 것은 막지 않음).
- E-6 **단원평가**(새 탭, 설계: `docs/superpowers/specs/2026-10-29-unit-test-design.md`)
  - 정답지 「문항 이원 분류 및 모범 답안」 한글 파일은 AI 없이 표로 읽는다(문항·평가 내용·행동 영역·정답·배점·채점 기준·교과서 쪽). 다른 모양·사진은 AI가 읽는다. 평가지는 교과·단원·회차와 발문을 채운다.
  - 반 전체 답안 스캔(PDF·사진)을 학생마다 나누고 이름 칸을 가린다. 번호는 학급 명단의 예외 번호를 건너뛴다.
  - 모아찍기(한 면에 2쪽)면 가로로 긴 장을 왼쪽·오른쪽 쪽으로 자르고, 양면 스캔의 거꾸로 나온 뒷면(둘째·넷째… 장)은 180° 돌린다(답안 올리기 설정, 바꾸면 올린 스캔을 다시 나누고 이 평가의 이름 칸은 지워 다시 정하게 함, 나누는 동안 채점은 기다림). 단원평가 문제지·정답지의 2쪽 모아찍기 PDF는 왼쪽 단을 먼저 읽는다(다른 메뉴의 PDF는 글 층 그대로).
  - 학생마다 AI가 답을 읽고, 고르기·기호·선 잇기·단답은 **앱이 정답과 맞춘다**. 서술형만 AI가 부분 점수를 제안한다. 엇갈리거나 확신이 낮은 칸은 노란 칸으로 선생님이 확인한다.
  - 학생 피드백: 점수, 틀린 문항(내 답·정답·평가 내용·교과서 쪽), 잘한 점·격려(AI, 번호·점수·평가 내용만 보냄). 결과지 한글 파일·인쇄(한 쪽에 2명, 「번호별로 한 장씩」을 켜면 번호마다 한 장), 번호별 복사.
  - 결과 쌓기(학년도마다): 성적 일람표(CSV·한글 파일), 학생별 누적, 반 약한 부분, 교과 평어 초안(수준·AI 문장·번호별 복사).
- E-7 **활동지**(새 탭 평가 › 활동지, 설계: `docs/superpowers/specs/2026-11-02-activity-grading-design.md`): 수업 중·수업 후 활동지(정답이 없거나 예시 답안·그림·주관식이 대부분)를 평가한다.
  - 1단계 넣기: 활동지 파일(학생용·교사용·(예시)가 한 파일이어도, 따로여도)과 빈 활동지·교사용 쪽 사진을 한꺼번에 넣는다. 머리에서 교과·단원·차시·제목·쪽을 채우고, 날짜로 학기를 정한다. 이름·전화번호·주민번호 줄은 빼고 넣는다.
  - 2단계 기준: AI가 문항마다 종류(고르기·짝짓기·단답·서술·그리기)·정답·○ 기준·△ 기준을 만들고 출처(교사용에서·정답에서·AI가 만듦·선생님이 고침)를 보인다. 선생님이 고치고 [기준 확정]한다(고치면 채점한 학생에 「다시 채점」).
  - 3·4단계 채점: 학생 스캔(학생당 쪽 수, 이름 칸 가리기, 적힌 번호로 맞추기)을 학생마다 AI 한 번으로 읽고 문항마다 ○·△·×·안 함(틀린 답은 ×, 그림은 표현까지)과 잘한 점·더 해 볼 점·수준(잘함·보통·노력, AI가 정함)을 낸다. 고르기·짝짓기·단답은 앱이 정답과 맞추고, 엇갈리거나 확신이 낮으면 노란 칸. 선생님이 칸·수준·글을 고친다. 검토 AI는 노란 칸만 본다.
  - 5단계 결과: 문항별 통계(× · 안 함 많은 문항 먼저), 반 표·피드백 쪽지(한 쪽에 4명, 「번호별로 한 장씩」을 켜면 번호마다 한 장, 번호만) 한글·워드·PDF·표 복사, [확정] → 학생별 모아 보기(번호·교과·학기).
  - 교과 평어에 참고하기(기본 꺼짐): 켜면 교과는 활동지 교과로 먼저 고르고 평가계획의 평가 영역을 고른다. 평가지 채점에서 그 평가요소를 고르면 「참고할 단원평가·활동지」(최근 5개 · [더보기], 기본 체크 안 함)에 나오고, 체크한 것만 학생별 평어 요청에 「참고:」 줄(번호만, 600자까지)로 붙는다. 단원평가도 같은 스위치를 「평가 정보」에 둔다.
- E-8 **한꺼번에 넣기**(단원평가·평가지 채점·활동지 공통, `core/bundle.js`): 정답·교사용과 문제지·학생 답안을 따로 넣지 않고 한 번에 넣어도 나눈다.
  - 한 파일 안: 「교사용」·「(예시)」·「예시 답안」·「[정답]」·「채점 기준」 줄이나 「이름: 교사용」에서 학생용 / 교사용으로 나누고, 표시 없이 같은 머리가 다시 나오면 거기서 나눈다. 학생용·교사용을 따로 넣으면 교사용 파일(이름·첫 줄·「이름: 교사용」)을 뒤로 두고 나눈다.
  - 스캔 묶음: 글자층이 있는 쪽은 정답·교사용 쪽. 글자가 없는 쪽이 3장 이상이면 앞 2쪽·뒤 2쪽만 작은 그림(이름 칸과 맨 위 띠를 가림)으로 AI가 정답·교사용 / 빈 활동지 / 학생을 고른다.
  - 나눈 것이 있으면 확인 카드(쪽마다 눌러 바꾸기, [나누지 않기])를 보이고 확인 뒤 넣는다. 학생 스캔만이면 카드 없이 넣는다.

### 5.2 품의
**화면**: 왼쪽 「메모」 칸(맨 위 「아무거나 넣기」), 오른쪽 「에듀파인에 붙여넣을 초안」 칸(맨 위 AI 줄). 헤더 오른쪽에 [템플릿으로 저장]·[새로 쓰기]. 탭: 새 품의 · 저장한 템플릿 · 최근 작성. (0.11.0 설계: `docs/superpowers/specs/2026-11-02-purchase-complete-design.md`)

- P-1 품의 종류: 물품 구입 · 강사 수당 · 행사 운영 · 협의회. 종류마다 입력 안내와 작성 예시를 보여 준다.
- P-2 입력: 사업명, 목적, 일시, 대상, 장소, 예산 과목(모르면 「모르겠어요 · 행정실 확인」), 총액(선택 — 배정받은 금액 등 맞춰 볼 금액이 있을 때), 품목(품명·규격·단위·수량·단가·구입처, 여러 줄. 강사 수당은 강사(역할)·시간·시간당 단가).
- P-3 견적서 올리기
  - 엑셀(.xlsx)·CSV: 앱이 직접 읽어 품목 표를 채운다(품명·규격·수량·단가 열을 찾음).
  - 사진(JPG·PNG)·PDF: AI가 읽어 품목 표를 채운다. 업스테이지는 글자 읽기(OCR) API로 글자를 뽑은 뒤 Solar가 표로 정리한다.
  - 읽지 못하면 「견적서 글자를 읽지 못했어요. 직접 입력해 주세요」라고 안내하고 품목 칸에 커서를 둔다.
  - 읽어 온 품목은 교사가 확인·수정할 수 있게 표에 넣을 뿐, 바로 초안을 만들지 않는다.
- P-4 [초안 만들기]를 누르면 AI가 제목과 품의 사유를 쓴다.
  - 제목: 한 줄. 예) 「5학년 과학 실험 재료(용해와 용액) 구입」
  - 품의 사유: AI가 쓴 첫 문장(「…을 다음과 같이 구입하고자 합니다.」) + 앱이 만드는 「가. 목적 / 나. 일시 / 다. 대상 / 라. 장소 / 마. 소요 예산: 금113,560원(금일십일만삼천오백육십원) / 바. 예산 과목 / 사. 산출 근거」(빈 칸은 빼고 다시 매김) + 붙임.
  - 산출 내역 표: 품명·규격·단위·수량·단가·금액·합계(구입처가 있으면 구입처 열). 금액과 합계는 앱이 계산한다.
  - 초안 뒤 품목·붙임이 바뀌면 손대지 않은 사유는 가~붙임을 다시 맞춘다. 손으로 고친 사유는 그대로 두고 [사유 다시 맞추기]를 보인다(첫 문단은 고친 그대로).
- P-5 칸마다 [복사]. 산출 내역은 [표 복사]로 탭 구분 글을 복사해 에듀파인·엑셀에 그대로 붙는다.
- P-6 확인 목록(초안 아래)
  - 필수 칸(목적·일시·대상·품목 1개 이상)이 비면 초안을 만들지 않고 빈 칸을 빨간색으로 표시한다.
  - 품목 금액의 합과 교사가 적은 총액(적었을 때)이 다르면 경고한다.
  - 예산 과목이 없으면 「예산 과목 · 행정실 확인 필요」.
  - 합계가 설정 › 품의 기준의 「계약 기준 금액」(기본 2,000만 원)을 넘으면 「별도 계약 절차 확인 필요」.
  - 문제가 없으면 「품목 금액의 합과 총액이 같아요」, 「주민번호·계좌번호가 들어 있지 않아요」처럼 확인한 내용을 보여 준다.
- P-7 개인정보: 어느 칸에든 주민등록번호 모양(6자리-7자리) 또는 계좌번호 모양(숫자·하이픈 10~16자리, 은행 이름과 함께)의 글자가 있으면 저장·초안 만들기를 막고 「개인정보는 넣지 말아 주세요」라고 그 칸을 표시한다. 강사 수당 품의에도 주민번호·계좌 입력 칸을 만들지 않는다.
- P-8 템플릿: [템플릿으로 저장]은 메모 전체(종류·사업명·목적·품목 구성(수량 포함)·붙임)를 이름 붙여 저장한다(일시는 비움, 50개). 「저장한 템플릿」에서 불러오면 날짜만 고치면 되게 채워지고, 쓰던 품의가 있으면 먼저 묻는다(쓰던 품의는 최근 작성에 남음). 이름 바꾸기·지우기(확인) 가능.
- P-9 최근 작성: 초안을 만들 때마다 최근 20개를 저장한다(같은 품의는 한 줄을 고쳐 맨 앞으로). [열기]로 그 메모·초안을 다시 연다. [새로 쓰기]는 빈 품의로 시작한다.
- P-10 행사계획에서 [품의로 이어 가기]로 들어오면 종류 「행사 운영」, 사업명·목적·일시·대상·장소, 예산 항목이 채워져 있다.
- P-11 아무거나 넣기(메모 맨 위 한 칸): 엑셀·CSV·한글·PDF 견적서 파일, 장바구니·견적서 캡처(붙여넣기·끌어 놓기), 대충 쓴 글을 넣으면 품목과 빈 칸을 채운다.
  - 글은 앱이 먼저 읽는다(「A4 용지 5박스 2만원」, 「보드마커 12개 1,500원」, 「총 36,000원」은 수량으로 나눈 단가, 목록 기호는 뺌). 못 읽은 줄이 있으면 AI가 글 전체를 한 번 읽는다. 캡처·사진은 AI가 읽는다.
  - 이미 쓴 칸은 덮지 않고 빈 칸만 채운다. 품목이 이미 있으면 [더하기]·[바꾸기]를 묻는다. 배송비는 「배송비」 품목 줄(단위 건, 규격·구입처에 판매처)로 넣는다.
  - 주문자·받는 사람 이름, 주소, 전화번호, 결제 수단은 AI에 쓰지 말라고 하고, 답에 있어도 버린다.
- P-12 구입처: 품목마다 구입처 칸. 구입처가 둘 이상이면 「구입처별로 나눠 품의할까요?」를 물어, 나누면 첫 구입처는 지금 품의에 두고 나머지는 「사업명 (구입처)」 새 품의로 최근 작성에 넣는다.
- P-13 종류별 계산 도우미: 물품·행사는 「부가세 포함」과 공급가액 기준 견적 안내(2천만 원 이하 1인 견적, 넘으면 2인 이상). 강사 수당은 소득 구분(기타소득 8.8%·사업소득 3.3%)과 강사별 원천징수·실지급액(참고). 협의회는 인원 × 1인 단가 × 횟수 → 품목 줄, 1인 단가가 설정 › 품의 기준의 「협의회 1인 상한」(기본 40,000원)을 넘으면 경고.
- P-14 예산 과목 추천: 종류·품명으로 일반수용비·교육운영비·운영수당·업무추진비·자산취득비 같은 칩을 보이고, 누르면 예산 과목 칸에 넣는다(참고용 · 행정실 확인).
- P-15 붙임 체크리스트: 「지출품의서 1부」는 늘 1번. 종류마다 기본(물품: 견적서 / 강사: 강사 카드·성범죄·아동학대 전력 조회 동의서 / 행사·협의회: 계획서 등)을 체크해 두고 직접 더할 수 있다. 사유 끝에 「붙임  1. 지출품의서 1부. … 끝.」으로 넣는다.
- P-16 업무별 AI 「품의」: 초안·아무거나 넣기·견적서 AI가 업무별 AI의 품의 AI를 쓴다. 검토를 켜면 초안 뒤 검토 AI가 메모와 제목·첫 문장을 한 번 보고(메모에 없는 사실, 금액·날짜를 문장에 씀, 종류와 맞지 않는 말, 개인정보) 그 칸 아래 두 의견을 보인다. [검토 안 쓰기]는 제목 또는 사유 첫 문장만 바꾼다(가~붙임 그대로). 손으로 고치면 의견은 사라지고, 실패하면 초안 그대로 「검토하지 못했어요」. 강사 칸 글은 초안·검토 AI 어디에도 보내지 않는다. 초안은 한글·워드·PDF로 내려받는다.

- P-17 **한 칸 → 바로 초안**(설계: `docs/superpowers/specs/2026-11-02-purchase-oneshot-notes-design.md`): 처음 화면은 종류·넣기 칸·[초안 만들기]. 누르면 넣은 것을 읽어(P-11) 빈 칸만 채우고 초안 AI 한 번(`[품의 초안]`)이 제목·첫 문장과 비어 있는 사업명·목적·일시·대상·장소(목적은 짐작 가능), 선생님이 종류를 누르지 않았으면 종류까지 낸다. AI가 채운 칸은 「AI가 짐작함」. 필수는 목적·품목 1개(일시·대상은 아님, 비면 사유에서 빼고 다시 매김). 초안 위 「확인할 것」 칩(예산 과목·단가 없는 품목·AI가 짐작한 목적·경고, 일시·대상 없음은 정보)을 누르면 접힌 [자세히 고치기]가 열리고 그 칸으로 간다(열림은 기억). 강사 수당은 넣은 글을 초안 AI로 보내지 않는다. 떠 있는 버튼으로 넣은 견적서는 초안까지 쓴다.
- P-18 설정 › 품의 기준 「넣는 방식」: 바로 초안(기본) / 빠진 것만 물어보기(목적·품목이 비면 그것만 묻는 창, 닫으면 초안을 쓰지 않음).

### 5.2.1 기타 › 쪽지 작성 (설계: `docs/superpowers/specs/2026-11-02-purchase-oneshot-notes-design.md`)
- M-1 세로 메뉴 「기타」 › [쪽지 작성]. 공문·연수 계획·행사 계획 파일 여러 개(한글·PDF·사진·txt)나 글을 넣으면 AI 한 번(`[쪽지 안내]`, 업무별 AI 「쪽지」)이 종류·제목·일시·장소·대상·신청 기한과 방법·준비물·유의 사항·주요 내용을 뽑는다. 글에 없는 것은 빈칸. AI로 보내기 전 명단 줄·전화번호 줄·주민번호 줄은 빼고 「이름: ○○○」은 이름을 지운다(뺀 수를 알림).
- M-2 쪽지 글은 앱이 맞춘다(0.15.0부터 이음에 제목 칸이 없어 본문 첫 줄이 제목, 인사는 「안녕하세요 선생님.」으로 고정): 「[연수 안내]·[회의 안내]·[행사 안내]·[제출 안내]·[안내] 제목」, 인사, □일시(「2026. 11. 12.(목)」, 요일은 앱이 셈, 여러 번이면 한 줄씩)·□장소·□대상·□신청·□준비물·유의 사항(있는 것만), 자세히일 때 □주요 내용, 「붙임  1. 이름 1부. … 끝.」, 「문의: 보내는 사람」(한 번 적어 두면 늘, AI로 보내지 않음), 「감사합니다.」. 짧게·기본·자세히는 AI를 다시 부르지 않는다. 칸을 고치면 본문이 다시 맞춰지고, 본문을 손으로 고치면 그대로 두고 [칸으로 다시 맞추기].
- M-3 붙임: 넣은 파일이 붙임 목록(체크·이름 고치기). Windows 앱은 [붙임 파일 복사](다운로드/쌤비서 쪽지 붙임/<날짜 제목>/에 저장 → 탐색기 Ctrl+C와 같은 쉘 데이터 개체·「Preferred DropEffect=복사」로 클립보드에, 이음 쪽지 창에 Ctrl+V)·「⠿」 끌어 놓기(OLE 끌기, 0.15.0)·[폴더 경로 복사](이음 [파일 첨부] 창 「파일 이름」 칸용, 0.15.0)·[폴더 열기]. 같은 이름·같은 내용은 다시 쓰고 다르면 「(2)」. 웹판은 목록만.
- M-4 최근 쪽지 20개(학년도 자료, 붙임은 이름만). [열기]·[다시 안내](제목 「[다시 안내] …」, 「다시 한번 안내드립니다.」). 떠 있는 버튼: 머리에 안내·연수·회의 같은 말이 있고 일시·장소·대상·신청·참석 중 둘 이상인 공문·계획은 「안내·제출 공문」(0.17부터 기타 › 공문 처리로, 거기서 [쪽지]), 지침·행사 계획서는 그대로.

### 5.2.2 에듀파인에 차례로 붙여넣기 · 계획 › 결과 보고 (0.15.0, 설계: `docs/superpowers/specs/2026-11-03-report-edufine-design.md`)
- Q-1 Windows 앱: 품의 초안·결과 보고 공문의 [에듀파인에 차례로 붙여넣기] → 앱이 Ctrl+V를 맡고(나이스 자동 붙여넣기와 같은 길, 둘 중 하나만), 브라우저에서 누른 Ctrl+V마다 다음 조각을 클립보드에 넣어 붙인다(여러 줄 그대로). 품의: 제목 → 품의 사유 → 산출 내역(칸마다: 품목마다 품명·규격·단위·수량·단가 / 표 한 번에). 공문: 제목 → 본문. 빈 조각은 건너뛰고, 앞으로·건너뛰기·목록에서 고르기, 쓰지 않은 채 15분이면 풀린다. 저장·결재·상신은 앱이 누르지 않는다.
- R-1 계획 › 결과 보고: 계획서·관련 공문·작년 보고서(한글·PDF·워드·글, 종류는 짐작해 칩으로·바꾸기), 「한 일」 메모, 사진 12장까지. 글은 명단·전화번호 줄을 빼고 저장·AI로, 글 없는 PDF는 쪽 그림 3장까지 AI로, 사진은 긴 변 1024px로 AI가 본다(교사 동의). 원본 파일·사진은 저장하지 않는다.
- R-2 AI 한 번(`[결과 보고]`, 업무별 AI 「결과 보고」, 검토 없음): 행사명·관련 문서(번호·날짜·제목)·기간·장소·대상·인원·주요 내용 한 줄·소제목별 줄(작년 보고서가 있으면 그 소제목 차례·문체)·사진 설명. 메모·문서에 없는 성과·숫자는 쓰지 않는다.
- R-3 앱이 맞춘다: 결과 보고 공문(「1. 관련: 번호(날짜) 「제목」」(둘 이상이면 가·나), 「2. 위 호와 관련하여 ○○ 운영 결과를 다음과 같이 보고합니다.」, 가. 일시(요일)·나. 장소·다. 대상(인원)·라. 주요 내용(빈 칸은 빼고 다시 매김), 「붙임  ○○ 운영 결과 보고서 1부.  끝.」), 결과 보고서(1. 개요 표, 2.~ 소제목(줄 앞 「- 」), 끝에 사진 자료: 2열 표, 사진과 설명). 한글(hwpx BinData·hp:pic)·워드(media·wp:inline)·PDF(인쇄 HTML img).
- R-4 칸을 고치면 공문을 다시 맞추고, 손으로 고친 공문은 그대로 두고 [칸으로 다시 맞추기]. 최근 결과 보고 20개(글·칸·사진 설명만). 행사계획 설문 결과 카드의 [결과 보고 공문·보고서 쓰기]는 그 행사의 계획서 글·설문 결과 보고서·행사 정보를 넣고 결과 보고로 간다.

### 5.2.3 기타 › 가정통신문 (0.16.0, 설계: `docs/superpowers/specs/2026-11-03-home-letter-design.md`)
- L-1 학교 양식: [양식 넣기](.hwpx·.hwp) → IndexedDB `ssam-forms`에 이름 붙여 저장(5MB까지, 학년도와 상관없음). 고른 양식은 `letter:form`. 없으면 기본 양식(학교 정보의 학교 이름, 「가 정 통 신 문」, 띄어 쓴 학교장 줄).
- L-2 .hwpx 양식은 작은 XML 읽개로 줄(표 칸 안 문단 포함)을 읽고 제목·본문(인사~붙임)·날짜·학교장·회신서 자리를 찾음({제목}·{본문}·{날짜} 표시가 있으면 그 자리). [양식 맞추기]에서 줄을 눌러 고치고 저장.
- L-3 채우기: 머리·로고·학교장 줄·그 밖의 개체는 그대로, 제목·날짜(양식 꼴: 「2026 . 11 . 3 .」·「2026년 11월 3일」)·본문만 바꾸고 바꾼 문단은 줄 배치 기억(linesegarray)을 지움. 본문 줄은 단계(1. 가. 1) 가) ① -)마다 양식의 같은 단계 문단 모양·글자 모양·앞 공백을 따름. 회신서를 켜면 옛 회신서 대신 자르는 선·회신서 제목·2열 표(학년 반 번호·학생 이름·칸)·제출 안내·보호자 서명(header.xml에 실선 테두리 더함), 끄면 옛 회신서만 지움(본문과 같은 표 안이면 지우지 않고 알림).
- L-4 .hwp 양식은 글만 읽어 머리 줄·학교장 줄·날짜 꼴을 얻고 쌤비서 문서(가운데 줄 블록 `c`)로 한글·워드·PDF.
- L-5 AI 한 번(`[가정통신문]`, 업무별 AI 「가정통신문」, 검토 없음): 공문·계획 글(명단·전화번호 줄 뺌), 넣을 내용, 양식의 옛 제목·본문(문체 참고, 머리·학교장 줄 빼고 전화번호·이메일 지움) → 제목·인사·취지·항목·맺음·회신서 칸·알림 앱 글·관련 공문·받는 사람. 앱이 본문(인사 → 취지 → 항목 → 맺음)과 발송 기안(관련 → 「…가정통신문을 다음과 같이 발송하고자 합니다」 → 가. 발송 대상·나. 발송일·다. 발송 방법 → 붙임 가정통신문 1부. 끝.)을 맞춤. 최근 20개.

- L-6 (0.17) 본문 표: 「|」로 시작하고 끝나는 줄이 이어지면 표(첫 줄 머리, 「|---|」 버림). .hwpx 양식은 표 문단(테두리는 header.xml에 한 번 더함), 기본 양식은 표 블록, 화면 미리보기. 행사계획 가정통신문 [학교 양식으로](AI 없이 제목·본문). 설계: `docs/superpowers/specs/2026-11-04-gongmun-reply-tables-design.md`
- L-7 (0.17) 회신서 모으기: 회신서 칸 중 □가 있는 칸만, 스캔(PDF·사진) → 이름 칸 가리기(가리기 편집기) → 쪽마다 가린 그림을 AI(`[회신서 읽기]`, 업무 「회신서 읽기」)로 번호·고른 선택지 → 번호 × 칸 표(겹친 번호·못 읽은 칸 노랑, 고르면 고쳐짐), 칸별 인원, 미제출(설정 › 학급 명단 번호), 탭 복사·한글·워드·PDF. 저장은 가린 칸·번호·답만.

### 5.2.4 기타 › 공문 처리 (0.17, 설계: `docs/superpowers/specs/2026-11-04-gongmun-reply-tables-design.md`)
- G-1 넣기: 공문 파일(파일마다 하나)·글 붙여 넣기·「쌤」 버튼(안내·공문). 명단·전화번호 줄을 뺀 글만 8천 자까지 저장(원본 파일 저장 없음), 40개까지.
- G-2 AI 한 번(`[공문 처리]`, 업무 「공문 처리」, 검토 없음): 제목·발신·문서번호·날짜·제출 기한·무엇을 내는지·요약·할 일 6개·넘길 곳. 연도 없는 날짜는 학년도(1~2월은 다음 해).
- G-3 목록: 끝나지 않은 것 → 기한 가까운 것(지난 것 먼저) → 기한 없음, 끝난 것은 접어서 아래. D-n(지남·D-day·D-1~3 색), 할 일 체크·더하기·빼기, 기한 고치기, [다 했어요]·[지우기].
- G-4 넘기기: [쪽지](이번에 넣은 파일은 붙임으로), [가정통신문](넣기 칸에 공문), [품의](새 품의 넣기 칸 → 바로 초안, 쓰던 품의는 최근에), [결과 보고](「관련 공문」).
- G-5 기한 보이기: 학사일정 달력(「[제출] 제목」·「[할 일] …」), 학급 › 오늘 수업 위 「공문 기한」 띠(7일 안·지난 것, 3개, 누르면 공문 처리).
- 결과 보고(0.17): 저장한 .hwpx 학교 양식을 고르면 보고서(개요 표·소제목·사진 표)를 그 양식에(날짜 자리는 없어도 됨).

### 5.3 연간계획
**화면**: 단계 표시(1 자료 넣기 → 2 작년 평가 → 3 지침 점검 → 4 초안 → 5 일정)와 「지난 계획」 목록.

- Y-1 자료 넣기
  - 업무명(필수), 학년도(설정값), 올해 목표(한두 문장, 필수)
  - 작년 계획서: .hwp·.hwpx·PDF 파일 또는 붙여넣기 (선택)
  - 작년 결과: 만족도 설문, 실적, 반성 메모 — 파일(.hwp·.hwpx·PDF·CSV·엑셀) 또는 붙여넣기 (선택)
  - 올해 지침·공문: 파일 또는 붙여넣기 (선택)
  - 학교 현황(학교명·학급 수·학생 수)은 설정 › 학교 정보에서 채우고, 담당자·예산은 여기서 적는다.
- Y-2 작년 운영 평가: 결과 자료가 있으면 AI가 「잘된 점 / 아쉬운 점 / 수치 변화」로 요약하고, 아쉬운 점마다 올해 개선 방향 2~3개를 제안한다. 교사는 반영할 제안에 체크한다. 결과 자료가 없으면 이 단계를 건너뛰고 「작년 결과 없이 목표와 지침으로 만들어요」라고 알린다.
- Y-3 지침 점검표: 지침 자료가 있으면 AI가 필수 항목을 뽑고, 초안에 들어갔는지 「반영됨 / 빠짐」으로 보여 준다. 빠짐 항목에는 넣을 문장을 제안하고 [넣기]로 초안에 더한다.
- Y-4 초안: 목적 → 방침 → 세부 추진 계획 → 월별 추진 일정 → 예산 → 평가 계획 순서. 작년 문장을 그대로 옮기지 않고 올해 목표·지침 표현으로 새로 쓴다. 단, 법령·근거 문장(「~법 제○조」 등)은 그대로 둔다. 항목마다 고칠 수 있다.
- Y-5 작년과 비교: 앱이 문장 단위로 작년 계획과 겹치는 정도를 계산해 「작년 계획과 ○○% 같아요」를 보여 주고, 60% 이상이면 겹치는 문장을 표시해 새로 쓰게 한다.
- Y-6 월별 일정: 일정마다 날짜를 정한다. 주말, 앱에 넣은 2026~2027년 공휴일, 설정의 방학·재량휴업일, 다른 계획의 일정과 겹치면 빨간색으로 표시하고 가까운 가능한 날짜 2개를 추천한다.
- Y-7 내보내기: [한글 파일로 내려받기]는 제목·문단·표(월별 일정, 예산)가 있는 .hwpx를 만든다. 항목별 [복사]도 둔다.
- Y-8 확정: [확정]하면 계획서와 월별 일정을 저장하고, 일정은 이 컴퓨터의 「학사일정」 목록에 넣는다(학급 메뉴·서버를 붙일 때 씀). 확정한 계획은 「지난 계획」에 남고, 다음 해에 「작년 계획서」로 불러올 수 있다.

### 5.4 행사계획
**화면**: 단계 표시(1 행사 정보 → 2 구성안 → 3 문서 → 4 설문·결과)와 「지난 행사」 목록.

- V-1 행사 정보: 종류(운동회·학예회·현장체험학습·기타), 목적, 대상 학년, 날짜, 장소(실내/야외), 예산, 참여 교직원(이름·맡은 업무, 선택), 작년 설문 결과(CSV·붙여넣기, 선택), 참고 자료(상위 계획·교육청 공문 등, 선택 — 연간계획에서 불러오기·파일·붙여넣기). 행사명·날짜·대상·장소는 필수.
  - 참고 자료는 구성안·문서를 만들 때 AI에 함께 보내 요구 사항(날짜·대상·필수 활동·안전 기준 등)을 지키게 하고, 반영한 것을 「참고 자료에서 반영한 것」으로 보인다.
- V-2 구성안: AI가 2~3개를 만든다.
  - 「보완안」: 작년 설문의 아쉬운 점을 고친 안 (작년 자료가 있을 때)
  - 「새로운 안」: 새 활동을 넣은 안
  - 각 안: 시간표, 장점, 필요 인력, 예산 내역. 하나를 고르고 시간표·활동을 고칠 수 있다.
- V-3 문서 세트: 고른 안으로 계획서 · 역할 분담표 · 안전 점검표 · 가정통신문을 만든다.
  - 역할 분담: 참여 교직원 명단이 있으면 업무를 배정하고, 한 사람에게 역할이 평균보다 2개 이상 많으면 앱이 표시한다. 직접 바꿀 수 있다.
  - 야외 행사는 안전 점검표와 우천 시 대체 일정이 있어야 [확정]할 수 있다.
  - 가정통신문은 학부모가 읽기 쉬운 말로 쓰고, 날짜·준비물·복장·문의처가 빠지면 [완성]할 수 없다(빠진 항목 표시).
  - 문서마다 [한글 파일로 내려받기]·[복사].
- V-4 [품의로 이어 가기]: 품의 › 새 품의로 넘어가며 행사 정보·예산을 채운다(P-10).
- V-5 확정: 행사 날짜를 학사일정 목록에 넣고, 가정통신문에 설문 QR을 넣을 자리를 만든다.
- V-6 만족도 설문
  - AI가 대상(학생·학부모·교직원)에 맞는 문항(5점 척도 4~6개 + 서술형 1~2개)을 만든다.
  - [구글 폼용 복사]로 문항을 복사하고, 교사가 만든 폼 링크를 넣으면 앱이 QR 그림(PNG)을 만든다. QR은 내려받기와 가정통신문 삽입이 된다.
  - 응답을 구글 폼에서 CSV로 내려받아 올리면, 문항별 평균·분포 그래프와 서술형 요약, 결과 보고서 초안, 내년 개선 메모를 만든다.
  - 응답이 10명 미만이면 「응답이 적어요(○명). 결과를 일반화하기 어려워요」라고 보고서에 표시한다.
  - 내년 개선 메모는 다음 해 같은 종류 행사의 「작년 설문 결과」로 불러올 수 있다.

### 5.4.1 학급운영계획 (설계: `docs/superpowers/specs/2026-10-29-class-plan-design.md`)

담임이 2~3월에 작년 학급운영계획(학급 교육과정 운영 계획)을 바탕으로 올해 계획서를 만든다. 학교마다 정해진 양식이 없으므로 작년 파일의 목차를 그대로 따른다.

- K-1 자료 넣기: 학년도·학년·반·남녀 학생 수(숫자만)·급훈, 작년 계획서(파일·붙여넣기·지난 학급운영계획에서 불러오기), 올해 지침(파일·붙여넣기), 첨부파일(진도표·평가계획·기타, 여러 개 — 종류를 짐작하고 바꿀 수 있음).
- K-2 목차: 작년 계획서의 목차(Ⅰ.·1. 또는 1.·가.)를 읽어 그대로 쓴다. 표 안 단원명·차례 줄은 목차가 아니다. 작년 파일이 없으면 표준 목차(학급 현황~월별 운영 계획, 학급 교육과정 운영 평가 항목을 모두 덮음). 이름 고치기·빼기·더하기·옮기기. 「시간 배당」 칸에 시수표, 「평가 계획」 칸에 평가 표, 「월별」 칸에 월별 표가 들어간다.
- K-3 초안: 칸마다 작년 글의 짜임과 문체를 따라 올해 글(학생 수·학년도는 올해 것). 올해 지침이 있으면 지침 항목을 먼저 뽑아 칸마다 「반영됨 · 빠짐 [넣기]」. 작년과 겹치는 정도(%). 칸마다 직접 고침.
- K-4 첨부: 진도표는 AI 없이 교과별 시수(총 시수, 없으면 차시 수)를 읽어 시수표로 넣고, 그 자리에서 [학급 › 진도표·시수에도 넣기]. 연간지도계획 표가 없으면 안내만 하고 붙임 목록에 넣는다. 평가계획은 AI로 교과·단원·성취기준·평가 방법·시기 표를 뽑아 고칠 수 있다.
- K-5 내보내기: 한글 파일(제목 「○학년도 ○학년 ○반 학급 교육과정 운영 계획」, 목차 번호, 칸 글, 시수표·평가 표·월별 표, 끝에 「붙임 1. 진도표(파일 이름) 1부.」), [확정]. 확정한 계획은 다음 해 「작년 계획서」로 불러온다.
- K-6 개인정보: 작년 계획서·지침·평가계획(파일·붙여넣기 모두)에서 사람 이름이 늘어선 줄(담임·학생 명단)과 전화번호 줄은 빼고, 한 줄에 하나씩 적힌 이름(임원·학생 명단 표의 이름 칸, 직책 옆 이름, 번호 명단)은 ○○○로 가리고, 뺀 줄·가린 이름 수를 알린다. 학생 수는 숫자만.

### 5.4.2 떠 있는 버튼 (설계: `docs/superpowers/specs/2026-10-30-inbox-button-design.md`)

어느 메뉴에 있든, 쌤비서 창이 닫혀 있어도(Windows) 파일 하나만 넣으면 쌤비서가 알아보고 그 기능을 한다.

- I-1 버튼: Windows 앱은 바탕화면 위 테두리 없는 「쌤」 창(항상 위, 끌어서 옮기고 위치 기억, 누르면 쌤비서 열기, 오른쪽 클릭: 쌤비서 열기·파일 고르기·버튼 숨기기·끝내기). 웹판은 오른쪽 아래 버튼(누르면 파일 고르기, 끌고 오면 「여기에 놓기」 판 — 다른 메뉴의 끌어 놓기 칸과 겹치지 않음).
- I-2 판단(AI 없음): 단원평가 정답지(합본 포함)·문제지·답안 스캔, 교과 평가계획, 작년 학급운영·행사·업무 계획, 올해 지침·공문, 진도표, 기초시간표, 학급 명단, 견적서, 설문 응답. 사진·글 없는 PDF는 이름으로만(정답→정답지, 견적→견적서, 그 밖은 답안 스캔). 여러 파일은 종류별로 묶어 정답지 → 문제지 → 답안 → 나머지 차례.
- I-3 확인 카드: 「○○(으)로 보여요(까닭)」, 할 일, [실행]·[다른 것으로]·[그만두기], 모자란 필수 값만 입력 칸. 설정 「바로 실행」이면 모자란 값이 없을 때 카드 없이. 카드가 떠 있는 동안 또 넣으면 줄을 세움. 읽을 수 없는 파일은 까닭만.
- I-4 실행: 정답지 → 새 단원평가, 문제지 → 교과가 같은(없으면 최근) 평가지 없는 단원평가, 답안 스캔 → 정답지 넣은 단원평가를 골라 채점 시작(없으면 평가지 채점), 교과 평가계획 → 교과 평어 평가계획, 작년 계획 → 새 계획 + 초안·구성안까지(설정 「자료로만」, AI 키가 없으면 자료로만 넣고 안내), 지침 → 고른 계획의 지침·참고 자료, 진도표 → 교과 고르기, 시간표 → 우리 반 시간표, 명단 → 명단 확인, 견적서 → 새 품의 품목(쓰던 품의가 있으면 더할지 고름), 설문 → 고른 행사의 결과 보고서.
- I-4a 같은 종류 여러 파일: 진도표·시간표·명단·교과 평가계획·문제지는 카드 한 번 뒤 파일마다 차례로(메뉴가 띄운 창이 닫힌 뒤 다음). 설문 CSV는 고른 행사에 첫 파일만 넣고 나머지는 다시 넣으라고 안내(한 행사의 결과를 덮지 않게). 한 파일에서 문제가 나도 다음 파일은 이어서.
- I-4b 창 안 끌어 놓기: 끌어 오면 버튼만 조금 커지고, 버튼 근처(오른쪽 아래)에서만 놓기 판. 판·메뉴 칸이 아닌 곳에 놓아도 창이 파일로 넘어가지 않음.
- I-5 설정 › 화면 › 떠 있는 버튼: 버튼 보이기 · 알아본 뒤(확인 카드/바로 실행) · 계획 파일(초안까지/자료로만) · (Windows) 쌤비서 창을 닫아도 버튼 남기기 · 컴퓨터를 켜면 버튼 띄우기.
- I-6 개인정보: 판단은 앱 안에서만. Windows 앱은 버튼에 끌어 놓은 경로만 읽음(한 파일 60MB까지).

### 5.5 연수 (화면 시안)
- T-1 내 필수연수: 연수명, 마감일, D-day, 상태(미이수·제출함·확인 완료·반려), 반려 사유, [이수증 올리기].
- T-2 연수 현황판: 연수별 이수율, 제출·미제출·반려 인원, 교직원×연수 상태표, [독려 알림], [엑셀 내려받기].
- 예시 자료로 채우고, 버튼은 「대회 이후 제공 예정」 안내만 한다.

### 5.6 학급 (동작 — 설계: `docs/superpowers/specs/2026-10-29-class-menu-design.md`)
- C-0 준비: 학교의 「교과-창체 연간지도계획」·「학년별 기초시간표」 한글 파일을 AI 없이 읽어 교과 진도표와 우리 반 시간표를 넣는다(다른 모양은 AI로 읽기·직접 쓰기).
- C-1 오늘 수업: 교시별 교과·단원·차시(단원 안 「5/14」)·쪽수, [완료 / 일부 진행 / 못 함], 체크하지 않은 날 알림.
- C-2 진도표·시수: 교과별 계획·실시·남은 시수, 진도 차이(예: 수학 +1, 국어 -2). 진도표의 기간 날짜(주) 또는 시간표 기준.
- C-3 주간학습안내: 진도표대로 이어지는 교시별 학습 내용 + 요일별 알림(학사일정·준비물·과제·안내장·안전), AI는 빈 칸 초안, [한글 파일]·[인쇄(PDF로 저장)]·[복사].

### 5.7 설정
- S-1 학급 명단: 학생 수(1~60), 예외 번호(전출 등), 학년. 평가가 함께 쓴다. 나이스 명렬표 같은 엑셀·CSV에서 **번호만** 가져올 수 있다(이름은 저장하지 않음).
- S-2 AI: Claude · Gemini · GPT · 업스테이지 중 하나를 고르고 키·모델을 넣는다. [연결 확인] 버튼으로 짧은 요청을 보내 키가 맞는지 확인한다. 키는 이 컴퓨터에만 저장한다.
- S-3 화면: 테마 5개(4.3). 기본은 다크 내비.
- S-4 학교 정보: 학교명, 학년도, 학급 수, 학생 수, 방학·재량휴업일(시작~끝, 여러 개).
- S-6 학년도: 학년도마다 자료를 따로 둔다(AI 키·테마는 공통). [백업 파일 만들기·불러오기](AI 키 제외), 보관한 학년도로 가기·지우기, [새 학년도 시작](연간계획·행사계획·새 학년도 학사일정·학교명은 가져가고 학급·평가 자료는 비움). 지난 학년도는 앱 안 보관함(IndexedDB)에 둔다. 학교 정보의 학년도는 「계획 학년도」.
- S-5 품의 기준: 계약 기준 금액(기본 2,000만 원), 협의회 1인 상한(기본 40,000원, 새 학년도에도 이어 감). 「학교마다 다를 수 있어요. 행정실에 확인해 주세요」라고 안내한다.

## 6. AI

### 6.1 제공자

| 제공자 | 글쓰기 | 이미지 읽기 | 비고 |
|---|---|---|---|
| Claude | 기존 그대로 | 직접 | 기존 코드 |
| Gemini | 기존 그대로 | 직접 | 기존 코드 |
| GPT | 기존 그대로 | 직접 | 기존 코드 |
| 업스테이지 | Solar (OpenAI 방식 `chat/completions`, `https://api.upstage.ai/v1`) | 글자 읽기 API로 글자를 뽑은 뒤 Solar에 넘김 | 모델 이름·이미지 지원·브라우저 호출은 첫날 공식 문서로 확인 |

### 6.2 공통 규칙
- 모든 AI 요청은 교사 PC에서 AI 회사로 바로 간다. 쌤비서 서버는 없다.
- 응답이 2분 동안 멈추거나 15분을 넘으면 끊는다(기존과 같음). 한도 초과(429)는 20초 쉬고 이어서, 네 번까지 다시 시도한다.
- 결과를 구조로 받아야 하는 곳(품목 표, 구성안, 점검표)은 JSON으로 받고, 읽지 못하면 한 번 다시 묻는다. 그래도 안 되면 「AI 답을 읽지 못했어요」라고 안내한다.
- AI 문장 만들기에 실패하면 입력한 내용을 그대로 둔 채 안내하고, 교사가 직접 쓸 수 있게 한다.
- 브라우저에서 업스테이지 호출이 막혀 있으면(CORS), Windows 앱은 Rust 명령으로 대신 요청한다. 웹판에서는 「업스테이지는 Windows 앱에서 써 주세요」라고 안내한다.

### 6.3 업무별 AI와 검토 AI (0.10.0, 설계: `docs/superpowers/specs/2026-11-02-ai-roles-design.md`)
- 업무 5개(`grade` 채점 · `writing` 평어·행특·창체 · `plan` 계획 초안 · `notes` 피드백·알림 · `purchase` 품의(0.11.0), 그 뒤 `message` 쪽지(0.13.0)·`report` 결과 보고(0.15.0)·`letter` 가정통신문(0.16.0), 셋 다 검토 없음)마다 메인 AI를 정한다. 정하지 않으면 기본 AI(설정 › AI). 그 밖의 AI 일은 기본 AI.
- 업무마다 검토를 켜면 검토 AI(업무에서 고른 것 → 설정 › AI의 기본 검토 AI)가 필요한 곳만 다시 본다: 단원평가 확신 없는 칸·서술형 부분 점수, 평가지 채점 「읽기 어려움」·수준 경계 학생, 평어·행특·창체 문장 10개씩, 계획 초안 한 번, 잘한 점·격려·주간 알림 한 번, 품의 제목·첫 문장 한 번.
- 두 의견이 다르면 노랗게 표시하고 [검토 안 쓰기]·[그대로 두기]로 교사가 고른다. 손으로 고치면 의견은 사라진다. 검토 AI가 실패하면 메인 결과는 그대로 두고 「검토하지 못했어요」, 그 차례의 남은 검토는 그만둔다.
- 저장 키 `ai-roles`(학년도와 상관없음)에는 회사·모델 이름만 둔다. 키가 지워진 회사를 정해 두었으면 기본 AI로 부르고 AI 줄에 알린다. Claude 계정(claude.ai 안)에서는 업무별·검토를 쓰지 않는다.
- 검토 AI에도 메인과 같은 것만 보낸다(이름 가린 그림, 번호·점수, 이름 없는 글).

### 6.4 채점 AI 요청 손보기 (0.14.0, 설계: `docs/superpowers/specs/2026-11-03-ai-cache-design.md`)

- 채점 세 곳(평가지·단원평가·활동지)과 그 검토 AI는 학생마다 같은 공통 부분(지시·정답표·평가지 글·문항 기준·평가지 채점의 기준 그림)을 **앞에**, 학생 그림·번호를 **뒤에** 보낸다. Claude는 공통 끝에 `cache_control`(5분)을 붙이고, Gemini·GPT는 같은 앞부분을 스스로 캐시한다. 업스테이지는 같은 그림을 다시 글자로 읽지 않는다.
- 단원평가·활동지는 처음 3명씩(Claude 계정은 2명), 잘되면 4명까지 동시에 채점한다. AI 한도에 걸리면 그 학생을 다시 줄에 넣고 동시 수를 줄여 20초 쉬었다가 이어 가며, 1명씩인데도 세 번 연달아 걸릴 때만 멈춘다.
- 채점이 끝나면 「AI 사용량: 보낸 양 …(그중 n%는 캐시로 싸게) · 받은 답 …」 한 줄을 보이고, 그 평가에 숫자만(`aiUse`) 남긴다.

## 7. 자료와 저장

- 모든 자료는 이 컴퓨터(브라우저 저장소)에 저장한다. 키 이름은 `ssam:`으로 시작한다.
- 모든 저장은 `core/store.js`를 거친다(`get`, `set`, `list`, `remove`). 나중에 학교 서버를 붙일 때 이 파일만 바꾼다.
- 스캔 이미지·견적서 사진은 저장하지 않는다(그 화면에서만 쓰고 버림).

| 자료 | 내용 |
|---|---|
| 설정 | 학급 명단, AI 제공자·키·모델, 테마, 학교 정보, 방학·재량휴업일, 계약 기준 금액 |
| 평가 | 평어 만들기 1.8.0과 같은 구조 (키 이름만 `ssam:` 아래로) |
| 품의 템플릿 | 이름, 종류, 사업명, 목적, 품목 구성 |
| 품의 기록 | 최근 20개: 입력 전체 + 초안 |
| 연간계획 | 업무명, 학년도, 입력 자료(글), 작년 평가, 선택한 개선 제안, 점검표, 초안, 월별 일정, 상태(작성 중/확정) |
| 행사 | 행사 정보, 구성안, 고른 안, 문서 세트, 설문 문항, 폼 링크, 설문 결과 요약, 결과 보고서, 내년 개선 메모 |
| 학급운영계획 | 학년도·학년·반·학생 수·급훈, 작년 계획서·지침(글, 이름 줄 뺀 것), 목차, 첨부(이름·종류·교과별 시수, 평가계획은 글), 지침 항목, 초안, 월별 활동, 평가 표, 상태 |
| 학사일정 | 날짜, 제목, 출처(연간계획·행사) |

## 8. 개인정보·보안
- 평가지·학습지는 이름 칸을 가리고 AI에 보낸다(기존과 같음).
- 품의는 주민등록번호·계좌번호 모양의 글자를 막는다(P-7).
- 학급운영계획·행사 설문은 이름이 늘어선 줄·열과 전화번호를 빼고 읽는다(K-6, `core/privacy.js`).
- AI 키는 코드·레포·로그에 남기지 않는다. 설정 화면에서는 가려서 보여 준다.
- 공개 레포에는 실제 학생·교직원·학교 자료를 넣지 않는다. 시연 자료는 지어낸 예시만 쓴다.
- README에 「자료는 내 컴퓨터에만 저장되고, AI 요청은 내 PC에서 AI 회사로 바로 간다」를 적는다.

## 9. 기술 구조

```
web/
  index.html        창 틀(세로 메뉴·헤더·본문 자리), 테마 적용, 메뉴 전환
  core/
    ai.js           AI 제공자 4개, 재시도·시간 제한·오류 문구, 이미지 처리
    store.js        저장 (지금은 브라우저 저장소)
    settings.js     설정 읽기·쓰기, 설정 화면
    files.js        파일 읽기: .hwp·.hwpx(기존 파서)·PDF(pdf.js)·사진·엑셀·CSV
    hwpx.js         .hwpx 만들기: 무압축 zip + 한글 문서 XML(문단·굵은 제목·표)
    ui.js           복사 버튼, 알림, 시트, 확인 목록, 단계 표시
    theme.css       테마 5개(테마 값만 다름)와 공통 모양
  menus/
    evaluate/       평어 만들기 1.8.0의 4개 탭 (거의 그대로 옮김)
    training/       시안
    plan/           연간계획, 행사계획, 학급운영계획
    class/          시안
    purchase/       품의
  vendor/           pdf.js, 엑셀 읽기, QR 만들기 — 앱 안에 넣어 인터넷 없이 동작
src-tauri/          Windows 앱: 자동 업데이트·나이스 자동 입력·프로그램 삭제(기존), 업스테이지 대신 요청(필요할 때)
tests/              Node 기본 테스트, Playwright 화면 시험
samples/            시연용 예시 파일
docs/               PRD, 구현 계획
```

- 빌드 도구 없이 ES 모듈(`<script type="module">`)로 나눈다. 빌드할 때 `web/` 전체가 실행 파일 하나에 들어간다.
- 웹판은 GitHub Pages로 연다(ES 모듈 때문에 파일을 더블클릭해 여는 방식은 지원하지 않음).
- Tauri: 앱 이름 「쌤비서」, 실행 파일 `ssam`, 식별자 `kr.doguri.ssam`(평어 만들기와 따로 설치·저장).
- 라이브러리는 정확한 버전으로 `vendor/`에 넣고 출처·라이선스를 `vendor/README.md`에 적는다.

## 11. 시험
- **Node 기본 테스트**(`node --test`): 금액·합계 계산, 주민번호·계좌번호 찾기, 날짜 겹침과 추천, 작년 계획과 겹치는 정도, 설문 CSV 읽기·집계, `.hwpx` 쓰기 → 기존 파서로 다시 읽기.

- **사람 확인**: 만든 `.hwpx`를 한글 프로그램에서 열기(선생님 PC), 실제 AI 키로 각 흐름 한 번씩.
