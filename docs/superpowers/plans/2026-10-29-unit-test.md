# 쌤비서 계획 7 · 평가 › 단원평가 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 단원평가 정답지(이원 분류표)·평가지를 읽고, 스캔한 학생 답안을 문항별로 채점(AI는 읽고 앱이 맞춤)하고, 학생 피드백(결과지·번호별 글)을 만들고, 결과를 쌓아 일람표·학생별 누적·반 약한 부분·교과 평어 초안으로 본다.

**Architecture:** 읽기·채점 규칙·저장·통계·문서·프롬프트는 DOM 없는 모듈(`web/menus/evaluate/unit/unit-*.js`)로 쓰고 Node로 시험한다. 화면은 평가 메뉴의 새 탭 「단원평가」로 끼우고, 스캔 읽기·이름 가리기는 기존 평가지 채점 코드를 `window.SSAM`으로 꺼내 쓴다. 저장은 학년도마다 따로인 `ssam:unit:*` 키.

**Tech Stack:** 계획 1~6과 같음. 새 라이브러리 없음.

**Spec:** `docs/superpowers/specs/2026-10-29-unit-test-design.md`

## Global Constraints
- 계획 1~6의 Global Constraints를 따른다(빌드 도구 없는 ES 모듈, 쉬운 우리말 안내, AI 키는 코드·레포·로그·백업에 없음).
- 학생은 **번호로만** 다룬다. 이름을 저장하거나 AI·결과지·글에 쓰지 않는다. 이름 칸 가리기 기본 켬. 스캔 이미지는 저장하지 않는다.
- 선생님이 보낸 실제 파일은 레포에 넣지 않는다. 시험·시연 자료는 같은 모양으로 지어낸다.
- 문항 유형: `choice` 고르기 · `symbol` 기호 · `match` 선 잇기 · `short` 단답 · `essay` 서술형. 부분 점수는 서술형만.
- 칸 표시(`flag`): `low`(AI 확신 낮음) · `differ`(앱과 AI 판단이 다름) · `similar`(단답을 AI가 뜻으로 맞다고 봄) · `essay`(서술형) · `''`. 선생님이 확인하면 `ok: true`, 점수를 고치면 `manual: true`.
- 저장 글 길이: `read` 120자, `why` 80자, 평가지 글 12,000자.
- 수준 기준 기본값: 최상 ≥ 95, 상 ≥ 80, 중 ≥ 60, 하 < 60 (100점 환산 평균).
- AI 프롬프트 첫 줄 표지: `[단원평가 채점]`, `[단원평가 정답지]`, `[단원평가 피드백]`, `[단원평가 평어]`.

## Review Focus
1. **정답지 모양이 조금 다름**(행동 영역이 3~4개, 머리 줄 위에 학교 이름·빈 줄, 칸 안 줄바꿈, 배점 칸이 비어 있음): 문항·정답·배점이 맞게 읽히고, 못 읽은 배점은 0으로 두고 정답표 확인에서 알린다. → Task 1 시험.
2. **AI가 답을 이상하게 줌**(문항을 빠뜨림, `points`가 배점보다 큼·음수·글자, `read`에 「③번」·「3번」·「(3)」처럼 섞어 씀): 빠진 문항은 빈 답·노란 칸(`low`), 점수는 0~배점으로 자름, 고르기 표기는 모두 같은 답으로 본다. → Task 2·4 시험.
3. **다시 채점**: 선생님이 고친 점수(`manual`)는 덮지 않는다. → Task 2 시험.
4. **채점 도중 다른 평가·다른 탭으로 감**: 결과는 시작한 평가·학생에 들어가고 보는 화면이 섞이지 않는다. → Task 6 화면 시험.
5. **저장 공간 부족**(한 평가 약 50KB): `saveTest`가 false면 「저장 공간이 모자라 저장하지 못했어요」, 화면은 그대로. → Task 3 시험(저장소 `setItem`이 던짐).
