# 쌤비서 계획 3 · 연간계획 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 계획 › 연간계획(PRD 5.3 Y-1~Y-8)을 동작하게 만든다: 자료 넣기 → 작년 평가 → 지침 점검 → 초안(작년과 비교) → 월별 일정(겹침·추천) → 한글 파일·확정.

**Architecture:** 날짜·공휴일·학사일정(`core/calendar.js`), 문서 글 읽기(`core/files.js`), 연간계획 모델·계산(`menus/plan/year-model.js`)은 DOM 없는 모듈로 써서 Node로 시험한다. 화면(`menus/plan/year.js`)은 단계마다 따로 그리고, AI는 계획 2의 `generateJSON`, 한글 파일은 `makeHwpx`를 쓴다. 행사계획(계획 4)이 `calendar.js`·`files.js`·단계 표시를 그대로 쓴다.

**Tech Stack:** 계획 1·2와 같음. 새 라이브러리 없음.

**Spec:** `docs/PRD.md` (5.3, 6.2, 7, 11, 12). 계획 1·2의 ledger `Ruling:` 줄.

## Global Constraints
- 계획 1의 Global Constraints를 따른다. 저장 키: `ssam:yearplans`(계획 목록), `ssam:yearplan:current`(보고 있는 id), `ssam:calendar`(학사일정). 올린 파일은 저장하지 않고 읽은 글만 저장한다.
- 날짜는 `YYYY-MM-DD` 글로 다루고, 요일 계산은 UTC로 한다(시간대에 따라 하루 밀리지 않게).
- 초안 순서와 이름: `purpose` 목적 → `policy` 방침 → `details` 세부 추진 계획 → `schedule` 월별 추진 일정 → `budget` 예산 → `evaluation` 평가 계획.
- 작년 문장을 그대로 옮기지 않는다. 단, 법령·근거 문장(「제○조」가 든 문장)은 그대로 두고 비교에서도 뺀다.
- 문구(PRD 그대로): 「작년 결과 없이 목표와 지침으로 만들어요」, 「작년 계획과 ○○% 같아요」, 「반영됨」·「빠짐」.
- AI 답은 `generateJSON`(계획 2)으로 받고, 실패하면 입력을 그대로 두고 `errorMessage`로 알린다.
- 밀리면 줄이는 순서(PRD 12): ① 지침 점검표(Task 5의 Y-3 부분).

## Review Focus
1. **공휴일·대체공휴일·방학이 겹친 날, 주말, 1월·12월 경계**: 겹침 이유가 모두 보이고 추천 날짜는 평일·공휴일·방학이 아닌 가장 가까운 날 2개. → Task 1 시험.
2. **망가진 `ssam:yearplans`·`ssam:calendar`(JSON 아님, 배열 아님, 칸 빠짐)**: 화면이 깨지지 않고 읽을 수 있는 계획만 보인다. → Task 3 시험.
3. **AI가 JSON 모양을 어김(섹션 빠짐, 일정 날짜가 `2027-13-40` 같은 값)**: 빠진 섹션은 빈 글, 이상한 날짜는 빈칸으로 받아 교사가 고르게 한다. → Task 3 시험(`normDraft`).
4. **작년 계획서가 아주 길거나(5만 자) 비었을 때**: 비교가 멈추지 않고(0.5초 안), 비었으면 비교 줄을 보이지 않는다. → Task 3 시험.
5. **AI가 쓰는 동안 다른 단계·메뉴로 감**: 답이 오면 그 계획에 저장되고, 돌아오면 보인다(다른 계획에 섞이지 않음). → Task 6 시험.
