# 수준별 기준표(루브릭) 만들기 → 평가지 채점·평어 (2026-11-16) — 설계

## 왜

충남교육청 「마주온 톡톡 2.0」이 「루브릭 설계, 서술형·논술형 채점」을 내세웠다. 쌤비서에는 서술형 채점(평가지 채점)은 있지만
수준별 기준표를 만드는 곳이 없다. 지금 평가지 채점의 기준은 셋뿐이다: 선생님이 직접 쓴 글, 정답표 파일, 평가계획의 상·중·하 한 줄씩.
쌤비서 방식(만든 것이 그대로 다음 일의 자료가 됨)으로, 평가요소의 **수준별 기준표를 만들고**, 그 표가 평가지 채점 기준과 평어의 바탕이 되게 한다.

선생님이 정한 것:
- 기준표는 **평가계획의 평가요소마다** 붙인다(추천 (가)).
- **수준별 기준표를 만드는 것이 중점**이다(채점·평어 쪽은 그 표를 쓰는 만큼만 고친다).
- 기준표는 **과목과 평가요소가 둘 다 같을 때만** 작동한다(평가요소 이름만 같은 다른 과목에는 쓰지 않는다).

## 목표

1. 평가요소 하나를 고르면 AI가 「채점 요소 × 수준」 기준표 초안을 만든다. 선생님이 칸마다 고치고 저장한다.
2. 같은 과목·같은 평가요소로 평가지를 채점하면 그 기준표로 채점한다. 학생마다 요소별 수준이 남는다.
3. 같은 과목·같은 평가요소의 교과 평어(수준별 문장 모음)와 평가지 채점 평어가 그 기준표의 수준 설명을 바탕으로 쓴다.
4. 기준표를 한글·워드·PDF로 내려받는다(평가계획 첨부·결재용).

## 하지 않는 것 (YAGNI)

- 기준표 보관함(따로 모아 두는 탭)·다른 학년도로 옮기기·학교끼리 나누기.
- 총점으로 수준을 정하는 절대평가 구간(평가지 채점의 수준 나누기는 지금처럼 비율).
- 학생용 자기평가표·학생에게 보여 주는 화면.
- 단원평가·활동지에 기준표 붙이기(단원평가는 문항별 채점 기준, 활동지는 ○·△ 기준이 이미 있음).
- 반 전체를 새 기준표로 한 번에 다시 채점하기(스캔은 저장하지 않음 — 새 채점으로).

## 하면 안 되는 것 (anti-goals)

- 과목이 다른데 평가요소 이름이 같다고 기준표가 들어가는 것.
- 학생 이름·교직원 이름이 기준표를 만들 때 AI로 가는 것.
- 기준표를 쓰면서 지금 채점 흐름(정답표·직접 쓴 기준·검토 AI·점수 맞추기·수준 비율·나이스 복사)이 깨지거나 예전 채점 기록을 못 여는 것.
- 휴대폰(390·360px)에서 기준표 칸이 가로로 넘치는 것.

## 지킬 것 (공통)

- CLAUDE.md 규칙 그대로: 학생 이름은 AI로 보내지 않음, 지어낸 이름만 시험에, 학급(`web/menus/class/**`)·연수 화면은 고치지 않음, 저장·결재 단추는 선생님이.
- 화면 말투 해요체·쉬운 말, 기존 부품(시트·카드·「화면 설명」·AI 줄·「AI로 가는 것」). 색만으로 수준을 나르지 않음(글자 함께).
- 저장은 `Store`(`ssam:` 키, 학년도마다 따로 — `core/years.js` GLOBAL에 넣지 않음).
- 새 기능이라 `core/chat-knowledge.js` 안내 항목과 `README.md` 기능 줄을 함께 더함.

## 방식 (Approaches)

- **(가) 평가계획의 평가요소마다 ← 고름.** 한 번 만들면 그 과목·평가요소로 채점할 때마다, 다른 반·다시 채점에도 그대로.
  학교 실무(평가계획에 평가요소별 채점 기준표를 붙임)와 같다.
  - 평가계획 없이 「직접 입력」으로 채점하면 과목·평가요소가 없으므로 **기준표를 쓰지 않는다**(「과목·평가요소가 같을 때만」 규칙에 맞춤).
    처음 추천에서는 「그 채점에만 붙임」이었으나, 그러면 채점을 시작하기 전에 기준표를 둘 곳이 없고(채점 기록은 첫 학생을 채점해야 생김) 규칙과도 어긋나 뺐다.
- (나) 채점할 때마다 따로: 가장 작지만 같은 수행평가를 다시 채점하면 다시 만들어야 하고, 교과 평어에는 못 씀.
- (다) 기준표 보관함 탭: 가장 크고, 평가요소와 잇는 일을 선생님이 손으로 해야 함. 지금 필요 없음.

## 기준표 모양 (자료)

```
rubric = {
  v: 1,
  subject, elem,            // 맞추는 열쇠: 과목·평가요소(화면에 보이는 그대로 저장)
  unit, std,                // 참고(단원·성취기준) — 맞출 때 쓰지 않음
  levels: ['high','mid','low'] | ['top','high','mid','low'],
  rows: [ { id, name, points, cells: { [lv]: { text, pts } } } ],   // 채점 요소 2~5개
  task,                     // 과제 설명(선생님이 쓴 글, 300자 안쪽 권장, 1,000자까지)
  at                        // 마지막으로 고친 때
}
```

- **열쇠**: `key = bare(subject) + '|' + bare(elem)`. `bare`는 띄어쓰기·문장부호를 뺀 글(evaluate.js `normKey`와 같은 규칙).
  과목이나 평가요소 어느 하나라도 비면 열쇠가 없고, 기준표를 평가요소에 붙이지 않는다.
  - 평가계획 줄의 평가요소가 비어 있으면(단원만 있는 줄) 화면 제목과 같게 `u.elem || u.unit`을 평가요소 이름으로 쓴다. (builder 몫으로 정함)
  - 한 평가계획 안에 같은 과목·같은 평가요소 줄이 둘이면(1·2학기) 기준표 하나를 같이 쓴다. 화면에 「같은 평가요소 n곳에 쓰여요」라고 알림.
- **수준**: 평가계획의 그 평가요소에 「최상」 기준(`crit.top`)이 있으면 4단계(최상·상·중·하), 없으면 3단계(상·중·하). 만들 때 [3단계·4단계]로 바꿀 수 있음.
- **배점(기본)**: 요소 배점 = 100을 요소 수로 나눈 값(나머지는 앞 요소부터 1점씩). 수준 점수는 배점에 곱해 반올림:
  3단계 상 1 · 중 0.7 · 하 0.4 / 4단계 최상 1 · 상 0.8 · 중 0.6 · 하 0.4. AI가 점수를 주면 앱이 위 범위로 고쳐 맞춤(위 수준 ≥ 아래 수준, 0~배점).
  선생님이 고친 점수는 그대로.
- **저장 키**: `ssam:rubrics` = `{ v: 1, items: { [key]: rubric } }` (학년도마다).
- **채점 기록의 사본**: 채점을 시작할 때(`grStart`) 그 평가요소의 기준표를 채점 기록에 그대로 복사해 둔다(`rubric`, `at` 포함).
  그 기록의 채점·다시 채점·점수 맞추기·검토 AI·평어는 모두 이 사본을 쓴다. 그래서 다른 평가계획을 열어 둔 채 지난 채점을 열어도,
  기준표를 그 뒤에 고치거나 지워도 그 기록은 채점할 때의 기준표 그대로다. (builder 질문 2 — 내가 정함)

## 화면

### 1. 들어가는 곳 (두 곳)

- **평가 › 교과 평어 › 평가요소 화면**: 「성취기준과 평가기준 보기」 바로 아래 한 줄.
  - 기준표가 없으면 `[수준별 기준표 만들기]`, 있으면 `수준별 기준표 · 요소 3개 · 3단계 [보기·고치기]`.
- **평가 › 평가지 채점 1단계 「무엇을 채점할까요」**: 「채점 기준·정답」 칸 위.
  - 고른 평가요소(과목·평가요소가 같은 것)에 기준표가 있으면 `수준별 기준표로 채점해요 · 요소 3개 [보기·고치기]`.
  - 없으면 `[수준별 기준표 만들기]`.
  - 「직접 입력」이면 단추 없이 작은 글 「평가요소를 고르면 수준별 기준표로 채점할 수 있어요」(평가계획이 있을 때만).
  - 채점 기록을 열었거나 채점 중(잠금)이면 그 기록의 사본을 [보기]만(고치기는 교과 평어 화면이나 새 채점에서).

### 2. 기준표 만들기·고치기 (시트, 넓은 화면은 넓은 시트)

```
수준별 기준표 · 3학년 수학 · 곱셈 원리 설명하기
(성취기준·평가기준 한 줄 요약 — 접힘)

과제 설명 (선택)  [ 두 자리 수 곱셈을 두 가지 방법으로 풀고 까닭을 씀        ]
채점 요소 수 [3 ▾]   수준 [3단계 | 4단계]          [✦ 기준표 만들기]

┌ 1. 곱셈 원리 이해 ─────────── 배점 [34] ─ [빼기] ┐
│ 상  [두 방법 모두 원리를 바르게 설명함        ] [34]점 │
│ 중  [한 방법으로 원리를 설명함               ] [24]점 │
│ 하  [식만 쓰고 설명이 없음                   ] [14]점 │
└──────────────────────────────────────────────────┘
(요소 카드 반복)                                   [+ 요소 더하기]

[✦ 다시 만들기]  [한글로 내려받기 ▾]          [닫기]  [저장]
```

- 요소 카드는 세로로 쌓음(휴대폰에서도 같은 꼴 — 표로 넓게 펴지 않음). 넓은 화면에서도 카드 꼴.
- 「과제 설명」에는 [한글 파일에서 가져오기](.hwpx·.hwp 글 읽기, 평가지 채점 정답표 읽기와 같은 도우미)도.
- [기준표 만들기]·[다시 만들기]는 지금 칸을 덮기 전에, 선생님이 고친 칸이 있으면 「고친 칸이 있어요. 새로 만들까요?」 묻기.
- 요소 2~5개(더하기·빼기 그 범위 안), 칸 글 200자까지. 빈 요소 이름·빈 칸이 있으면 [저장] 앞에 그 칸 표시하고 저장은 함(빈 칸은 「(비어 있음)」으로 보내지 않고 뺌).
- 배점 합이 100이 아니면 「배점 합 92점 — 채점은 100점으로 바꿔 셈해요」 알림(막지 않음).
- [저장] → `ssam:rubrics`의 그 열쇠에. 닫을 때 저장하지 않은 것이 있으면 묻기.
- 기준표를 지우는 [이 기준표 지우기](묻고)도 시트 아래에.
- 「AI로 가는 것」: 「학년·과목·단원·성취기준·평가요소·평가기준과 과제 설명을 보내요. 학생 자료는 보내지 않아요. 교직원 이름·연락처는 가려 보내요.」

### 3. AI 기준표 만들기

- AI 업무: `plan`(「계획 초안·문항 만들기」 — 문항 만들기와 같은 줄).
- 보내는 것: 학년, 과목, 단원, 평가영역, 평가요소, 성취기준(700자까지), 수업·평가 방법(700자까지), 평가기준(수준별 한 줄), 과제 설명(`core/redact.js`로 가림), 요소 수·수준.
- 요청: 「성취기준과 평가기준에서 나온, 겹치지 않는 채점 요소 n개. 수준마다 관찰할 수 있는 행동으로(학생이 무엇을 쓰거나 하면 그 수준인지), 위 수준은 아래 수준을 포함하게, 부정적인 말 대신 해낸 것 중심으로(하 수준도). 개조식 한 문장, 80자 안쪽.」
- 답(JSON): `{ "rows": [ { "name": "...", "points": 34, "cells": { "high": { "text": "...", "pts": 34 }, ... } } ] }`.
  앱이 고침: 요소 수 맞추기(넘치면 자르고 모자라면 있는 만큼), 수준 키 맞추기(없는 수준 칸은 빈 글), 배점·점수 범위(위 규칙), 글 다듬기(줄바꿈·따옴표 빼기, 200자).
  요소가 하나도 없으면 오류 「기준표를 만들지 못했어요. 다시 해 볼까요?」.
- 과제 설명의 가린 이름은 돌아온 글에서 되돌림(redact `back`), 깨진 자리 표시가 남은 칸은 빈 글.

## 채점 (평가지 채점)

- 쓰는 기준표: 채점을 시작할 때 고른 평가요소와 `key`가 같은 `ssam:rubrics` 기준표 → 채점 기록 사본(위). 없으면 지금 그대로(아래 모두 기준표가 있을 때만).
- `grGradeParts` 공통 글에 `[수준별 채점 기준표]` 블록을 더함(직접 쓴 기준·정답표 글은 그대로 함께):
  ```
  [수준별 채점 기준표] (배점 합 100점)
  1. 곱셈 원리 이해 (34점) — 상(34점): … / 중(24점): … / 하(14점): …
  ```
- **점수 (builder 질문 1 — 내가 정함)**: 기준표가 있으면 지금 할 일 2번의 고정 구간(90 이상 최상·70~89 상·40~69 중·39 이하 하)을 빼고 이렇게 바꿈:
  - 요소마다 기준표의 수준 하나를 고름. 그 요소를 비웠거나 전혀 하지 않았으면 `none`(0점, 화면 「안 함」).
  - **기준 점수** = 고른 수준 점수 합 ÷ 배점 합 × 100(반올림, 앱이 셈).
  - **최종 점수**는 기준 점수 −4 ~ +4 안에서, 같은 기준 점수인 학생끼리 답안의 차이를 드러내게 매김(0~100). 앱이 그 범위로 잘라 맞춤.
    (기준표 합만 쓰면 점수가 열 가지 남짓이라 수준 비율로 나눌 때 번호 순으로 갈리므로, 작은 범위에서만 AI가 차이를 둠.)
  - 요소 수준이 빠지거나 모르는 요소·수준이면 그 요소는 버리고, 남은 요소가 하나도 없으면 AI 점수를 자르지 않고 그대로 씀.
- 답 JSON에 `"rubric": [{ "name": "요소 이름", "level": "high" | … | "none" }]`를 더함. 학생 기록에 `rb: [{ name, level }]`, 기준 점수 `rbBase`로 저장.
  예전 기록(없음)은 지금처럼.
- **점수 맞추기(`grCalibPrompt`)**: 기준표가 있으면 고정 구간 문장을 빼고, 기준표 블록 + 학생마다 `기준 점수·요소별 수준`을 주고 「기준 점수 −4~+4 안에서만 고침」. 앱이 학생마다 그 범위로 잘라 맞춤. `rb`는 바꾸지 않음.
- **검토 AI(`grReviewScores`)**: 같은 채점 글(기준표 블록 포함)로 다시 채점하므로, 지금 점수를 받아들이는 방식 그대로 `rb`·`rbBase`도 함께 받아들임.
- 결과 화면 학생 줄: 평어 위에 작게 `기준표 · 곱셈 원리 상 · 풀이 과정 중 · 설명하기 안 함`(글자, 수준 색은 덧붙이기만 — 전체 수준 칩과 따로 보이게 「기준표」를 앞에).
- 기준표를 채점 뒤에 고치면 기록 사본은 그대로. 기록을 열었을 때 지금 기준표(찾을 수 있으면)의 `at`이 사본과 다르면 한 줄
  「이 채점은 채점할 때의 기준표로 했어요. 바뀐 기준표는 새 채점부터 써요.」 — 반 전체 다시 채점 단추는 만들지 않음(스캔은 저장하지 않으므로).

## 평어

- **평가지 채점 평어 (builder 질문 3 — 내가 정함)**: `grEvList`에 학생 `rb`마다(「안 함」 빼고) 근거 줄
  `기준표 「곱셈 원리 이해」: 두 방법 모두 원리를 바르게 설명함`(kind `gr`, 사본의 칸 글)을 더함. 수준 이름은 근거 줄에 넣지 않음
  (3단계 기준표의 「상」과 평어 수준 4단계의 「상」이 섞이지 않게). 평어의 수준은 지금처럼 전체 수준(비율로 나눈 것·선생님이 옮긴 것)이 정하고,
  근거 줄은 학생이 실제로 한 일로만 씀 — `grWritePrompt`에 「기준표 근거는 학생이 한 일이에요. 문장의 수준은 위 [수준]을 따라요」 한 줄.
- **교과 평어(수준별 문장 모음)**: 같은 과목·평가요소의 기준표가 있으면 `buildPrompt`에 그 수준의 요소별 설명을 더함:
  `[수준별 기준표 — 상] 곱셈 원리 이해: … / 풀이 과정: … / 설명하기: …` + 「이 설명에 나온 행동을 골고루 담되 문장마다 다르게」.
  최상 수준인데 3단계 기준표면 상 설명을 「한 걸음 더 나아간」 바탕으로 씀(지금 최상 안내와 같은 말).
  기준표를 바꿔도 이미 만든 문장은 그대로(선생님이 [다시 만들기]).

## 내려받기

- 문서(core/doc-export.js, 한글·워드·PDF, 형식 기억 그대로): 제목 「{평가요소} 수준별 채점 기준표」, 한 줄 「{학년} {과목} · {단원} · 성취기준 …」,
  표 머리 `채점 요소 | 배점 | (수준 이름…)`, 칸마다 「설명 (n점)」. 과제 설명이 있으면 표 위에 「과제」 한 줄. 파일 이름 `수준별 기준표-{과목}-{평가요소}`.

## 채팅

- `chat-knowledge.js`: 「수준별 기준표(루브릭)」 항목 — 어디서 만드는지(교과 평어 평가요소 화면·평가지 채점 1단계), 과목·평가요소가 같을 때만 채점·평어에 쓰인다는 것.
  지금 「루브릭」 낱말은 평가지 채점 안내로 가므로, 새 항목이 「루브릭」「기준표」「채점 기준표」를 받고 평가지 채점 탭으로 감.

## 시험

- 단위(`tests/unit/rubric*.test.mjs`, 지어낸 자료만):
  - 열쇠: 띄어쓰기·문장부호만 다르면 같은 열쇠, **과목이 다르면 평가요소가 같아도 다른 열쇠**, 과목·평가요소 하나라도 비면 열쇠 없음.
  - 기본 배점·수준 점수(3·4단계, 나머지 나누기), AI 답 고치기(요소 수·수준 키·범위·글 다듬기·빈 답 오류), 되돌리기(가린 이름).
  - 프롬프트: 평가 정보가 들어가고 학생 자료 칸이 없음, 교직원 이름·전화가 가려짐.
  - 채점 블록 글·배점 합 100 아님 알림 글, 학생 `rb` 정리(모르는 요소·수준 버림, `none` 0점), 기준 점수 셈(배점 합이 100이 아닐 때 포함),
    ±4 자르기(모든 요소가 빠지면 자르지 않음), 평어 근거 줄(수준 이름 없음·「안 함」 뺌), 교과 평어 수준별 줄.
  - 문서 블록(머리·칸 글·파일 이름).
- 화면(`tests/e2e/rubric.mjs`, 가짜 AI):
  - 교과 평어 평가요소 화면 → [수준별 기준표 만들기] → 만들기 → 칸 고치기 → 저장 → 다시 열면 그대로.
  - 평가지 채점에서 같은 과목·평가요소를 고르면 「수준별 기준표로 채점해요」가 보이고, 채점 요청 글에 기준표 블록이 들어가고, 결과 줄에 요소별 수준이 보임.
  - **같은 평가요소 이름의 다른 과목**을 고르면 기준표가 보이지 않고 요청 글에도 없음.
  - 「직접 입력」에는 기준표 단추가 없고 요청 글에도 없음.
  - 채점한 뒤 기준표를 고쳐도 그 기록을 열면 사본 그대로(요소별 수준·평어 근거), 「바뀐 기준표는 새 채점부터」 한 줄이 보임.
  - 기준표가 있을 때 채점 글에 고정 구간 문장이 없고, 점수가 기준 점수 ±4 안으로 잘림(가짜 AI가 범위 밖 점수를 줘도).
  - 휴대폰 390·360px: 시트가 가로로 넘치지 않고 누르는 칸이 겹치지 않음. 페이지 오류 없음.
- 기존 평가지 채점·교과 평어 e2e가 그대로 통과.
