# 떠 있는 버튼 (아무 파일이나 넣으면 알아서) 설계

날짜: 2026-10-30 · 요청: 「두근뽑기처럼 항상 올라와 있는 플로팅 버튼을 만들어서 어떤 파일이든 넣으면 판단해서(평가지인지, 계획인지) 평가지면 채점, 계획이면 기존 입력된 값으로(혹은 추가 입력 팝업 모달로 입력받음) 같은 기능을 만들어 줘.」

## 1. 선생님이 고른 것

- 버튼 위치: **바탕화면 위** — Windows 앱은 두근뽑기처럼 테두리 없는 작은 창이 모든 창 위에 떠 있음. 웹판은 화면 구석 버튼.
- 판단 뒤: **확인 카드 뒤 실행**, 설정에서 **바로 실행**으로 바꿀 수 있음.
- 계획 파일: 기본은 **초안까지**, 설정에서 **자료로만 넣고 열기**로 바꿀 수 있음.
- 다룰 파일: **평가·계획·학급·품의·설문** 모두.
- 쌤비서 창을 닫으면: **버튼은 남음**, 설정에서 바꿀 수 있음(같이 닫힘). 컴퓨터를 켜면 버튼 띄우기도 설정.
- 학생 답안 스캔: **단원평가 먼저**(정답지 넣은 평가 중 고르기, 최근 것 먼저), 없으면 평가지 채점.
- 카드·입력 창: **쌤비서 창을 앞으로** 띄워 그 안에.

## 2. 짜임

1. **버튼 창 (Windows, `bubble`)**: 72px 둥근 「쌤」 버튼, 테두리 없음·투명·항상 위·작업 표시줄에 안 보임. 끌어서 옮기고 위치를 기억(모니터 밖이면 오른쪽 아래). 파일을 끌어 놓으면 그 **경로만** 쌤비서(Rust)에 넘기고 쌤비서 창을 앞으로. 누르면 쌤비서 열기, 오른쪽 클릭 메뉴: 쌤비서 열기 · 파일 고르기 · 버튼 숨기기 · 끝내기.
2. **웹판 버튼**: 화면 오른쪽 아래 둥근 버튼. 누르면 파일 고르기(여러 개). 파일을 끌고 오면 버튼이 커다란 「여기에 놓기」 판이 되고, 그 위에 놓아야 받음(다른 메뉴의 끌어 놓기 칸과 겹치지 않게). Windows 앱에서 버튼 창을 켰으면 쌤비서 창 안 버튼은 숨김.
3. **받는 곳 `core/inbox.js`**: 파일 글을 읽고 → 종류 판단(`core/inbox-classify.js`, AI 없음) → 확인 카드 → 그 메뉴로 가서(`shell.go`) 그 메뉴가 등록한 처리 함수를 부름.
4. **각 메뉴의 처리 함수**: 메뉴 모듈이 `registerInbox(kind, handler)`로 등록(메뉴 안의 파일 읽기 함수를 그대로 씀). 옛 평가 화면(evaluate.js)은 `SSAM.inbox`로 평가계획 넣기·평가지 채점 넣기를 내놓음.

## 3. 종류 판단 (AI 없이, `classify({ name, text, scan }) → { kind, why, alts }`)

| 종류 | 근거 (점수가 가장 높은 것) | 하는 일 |
|---|---|---|
| `unit-key` 단원평가 정답지(합본 포함) | 정답지로 읽힘(`parseKey`), 이름에 정답·해설 | 새 단원평가 → 정답지 넣기(합본이면 평가지도) |
| `unit-paper` 단원평가 문제지 | 문항 3개 이상 + ①~⑤·답 칸, 이름에 문제지·평가지 | 평가지가 없는 최근 단원평가에(없으면 새 단원평가) |
| `unit-scan` 학생 답안 스캔 | 사진, 글이 없는 PDF | 정답지 넣은 단원평가 고르기 → 답안 넣고 채점 시작. 없으면 평가 › 평가지 채점 |
| `eval-plan` 교과 평가계획 | 성취기준 + 평가 요소·기준 + 상·중·하 | 평가 › 교과 평어 평가계획 넣기(지금 계획을 바꾼다고 카드에 적음) |
| `class-plan` 작년 학급운영계획 | 학급 (교육과정) 운영·경영 계획, 급훈·학급 실태 | 학급운영계획 새 계획(작년 계획서) |
| `event-plan` 작년 행사 계획 | 운동회·학예회·체험학습·축제 … + 계획 | 행사계획 새 행사(참고 자료) |
| `year-plan` 작년 업무 계획 | 운영·추진·연간 계획 + 목적·방침·세부 추진·예산 | 연간계획 새 계획(작년 계획서) |
| `guide` 올해 지침·공문 | 지침·공문·시행·안내·교육청, 수신·발신 | 어느 계획에 넣을지 고르기(연간·행사·학급운영, 지금 계획 또는 새로) |
| `jindo` 진도표 | 「교육과정 연간지도계획」 | 학급 › 진도표·시수 교과 고르기 |
| `timetable` 기초시간표 | 시간표 + 요일 칸 | 학급 › 시간표 가져오기(학년·반이 없으면 입력 창) |
| `roster` 학급 명단 | 번호 + 성명·이름 머리, 번호가 늘어선 표 | 설정 › 학급 명단 가져오기 |
| `quote` 견적서 | 「견적서」, 품명·규격·수량·단가 | 품의 › 새 품의에 품목 넣기 |
| `survey` 설문 응답 | CSV 첫 줄 「타임스탬프·Timestamp」 | 행사 고르기 → 결과 보고서 |
| `unknown` | 점수가 낮음 | 카드에서 고르기 |

- 사진·스캔 PDF는 **AI로 판단하지 않음**(학생 이름이 보일 수 있음). 이름에 「정답」이면 정답지(사진 정답지는 단원평가가 AI로 읽음), 「견적」이면 견적서, 그 밖은 답안 스캔.
- 한 번에 여러 파일: 종류별로 묶어 한 번씩 처리(답안 사진 여러 장 → 한 번 채점, 정답지+문제지 → 같은 단원평가). 차례: 정답지 → 문제지 → 답안 → 나머지.

## 4. 확인 카드와 입력 창

- 카드: 「○○으로 보여요 (까닭)」 + 할 일 + [실행] [다른 것으로 ▾] [그만두기]. 고른 종류에 모자란 값이 있으면 같은 카드에 입력 칸.
- 모자란 필수 값(이미 넣은 값은 채워 둠): 연간계획 업무명·목표 / 행사계획 행사명·대상·날짜·장소 / 학급운영계획 학년·반(학급 정보에 없을 때) / 시간표 학년·반 / 답안 스캔은 어느 단원평가 / 지침은 어느 계획 / 설문은 어느 행사.
- 바로 실행: 모자란 값이 없고 종류가 `unknown`이 아니면 카드 없이 실행.

## 5. 계획 「초안까지」

- 연간계획: 새 계획 + 작년 계획서 + 업무명·목표 → 4단계로 가서 초안 쓰기.
- 행사계획: 새 행사 + 참고 자료 + 행사 정보 → 2단계 구성안.
- 학급운영계획: 새 계획 + 작년 계획서(학년·반·학생 수는 학급 정보·명단) → 3단계 초안.
- 「자료로만」이면 같은 새 계획을 만들어 자료에 넣고 1단계를 엶. AI 키가 없으면 자료로만 넣고 안내.

## 6. 견적서 읽기 (품의, 새로 만듦)

xlsx·CSV는 `readTable` → `findItems`로 품목(품명·규격·수량·단가)을 AI 없이 읽어 새 품의 품목에 넣음. 사진·PDF는 AI로 읽음(`[견적서 읽기]` → `{ vendor, items }`). 품의 화면의 견적서 칸에 [견적서 넣기]도 같은 함수.

## 7. 설정 › 화면 › 떠 있는 버튼

켜기 · 판단 뒤(확인 카드 / 바로 실행) · 계획 파일(초안까지 / 자료로만) · 쌤비서 창을 닫으면(버튼은 남음 / 같이 닫힘, Windows) · 컴퓨터를 켜면 버튼 띄우기(Windows). 키 `ssam:inbox`, 버튼 위치 `ssam:bubble` — 학년도와 상관없는 설정(GLOBAL).

## 8. Windows 앱

- `tauri.conf.json`에 `bubble` 창(`bubble.html`, 72×72, decorations·shadow 없음, transparent, alwaysOnTop, skipTaskbar, resizable false, dragDropEnabled true, 처음엔 숨김).
- `src-tauri/src/bubble.rs`: `bubble_config({enabled, keepOnClose, autostart})`, `inbox_take(paths)`(끌어 놓은 경로를 허용 목록에 넣고 main 창에 `inbox:files` 알림, 창을 앞으로), `inbox_read(path)`(허용 목록에 있는 경로만, 60MB까지 바이트), `bubble_action(open|hide|quit)`. main 창 닫기: 버튼이 켜져 있고 「버튼은 남음」이면 숨김.
- 같은 앱을 또 켜면 이미 켜진 쌤비서를 앞으로(`tauri-plugin-single-instance`). 컴퓨터를 켜면 버튼 띄우기는 `tauri-plugin-autostart`(인수 `--bubble`: 쌤비서 창은 숨기고 버튼만).
- 버튼 창 권한(capability `bubble`): 끌기·위치·메뉴·이벤트·invoke.

## 9. 개인정보·안전

- 판단은 앱 안에서만. 버튼에 넣은 파일 글은 AI로 보내지 않음(각 기능이 원래 하던 대로만: 계획은 이름 줄 빼기, 답안은 이름 칸 가리기).
- Windows 앱은 끌어 놓은 경로만 읽음(웹 화면이 임의 경로를 읽을 수 없게).

## 10. 시험

- 단위: 종류 판단 15가지(지어낸 글, 기존 시험 자료 재사용), 여러 파일 묶기·차례, 설정 기본값, 견적서 표 읽기.
- 화면(웹판): 버튼 보임·파일 고르기·끌어 놓기 판, 정답지 → 새 단원평가, 답안 사진 → 평가 고르기 → 채점 시작(가짜 AI), 학급운영계획 → 초안, 연간계획 → 업무명·목표 입력 창 → 초안, 행사 → 입력 창 → 구성안, 지침 → 계획 고르기, 진도표·명단·설문·견적서, 모름 → 고르기, 바로 실행, 자료로만, 다른 메뉴의 끌어 놓기 칸과 겹치지 않음, 390px.
- Windows 버튼 창은 빌드(Actions, 릴리즈 없이)와 사람 확인 목록.
