# 학습 결손 찾기 → 기초학력 잇기 · 근거가 보이는 평어 — 설계 (2026-11-13)

선생님 요청: 비교표(혁신성·교육적 가치)에서 추천한 기능 2번·5번을 만들어 줘.
선생님이 고른 것: 근거는 **단원평가 교과 평어·평가지 채점 평어·행동특성** 모두에, 근거 없는 문장은 **주황 「근거 없음」 표시**(문장은 그대로),
미도달 기준 **60% 아래**(화면에서 바꿀 수 있게), 사후 점수 **자동 + 직접 입력**.

## 공통 규칙
- 학생은 번호로만 맞춤(모든 평가 자료의 공통 열쇠는 `no`). 이름은 AI로 보내지 않음(기초학력의 이름은 이 기기에만, AI에는 학생A·학생B).
- 저장 키·모양은 기존 그대로 두고 필드만 더함(예전 자료는 그대로 읽힘). 화면 글은 해요체·짧게, 색만으로 뜻을 나르지 않음(글·기호 함께), 누르는 칸 44px, 390px에서 가로로 넘치지 않음.
- 복사·[전체복사]·나이스 붙여넣기에는 지금처럼 평어 글만 들어감(근거 표시는 화면에만).
- 시험: 순수 함수는 Node 단위 시험, 화면은 e2e(가짜 AI). 글·이름은 모두 지어낸 것.

## 2. 학습 결손 찾기 → 기초학력으로 잇기

### 2-1. 찾기 (평가 › 단원평가 › 결과 모아 보기, `web/menus/evaluate/unit/unit-results.js`)
- 새 카드 **「도달하지 못한 학생」**: 지금 결과 화면에서 고른 교과·학기의 다 채점한 단원평가를 모아, 학생 번호마다 **영역(문항의 `domain`)별 점수율**을 셈.
  영역이 없는 평가는 그 평가 총점(%)을 「평가 이름」 한 영역으로 셈. 기준(기본 60%) **아래**인 영역이 하나라도 있는 학생만 보여 줌.
- 줄: `□ 3번 · 수와 연산 45% · 도형 52% (평가 3개)` — 낮은 차례, 영역 3개까지. 기준 칸(숫자, 40~90, 기본 60)은 단원평가 설정(`unit:set`의 `gapCut`)에 기억.
- 학생을 체크하고 **[기초학력에 넣기]** → 시트: 지금 있는 기초학력 프로그램 고르기 또는 [새 프로그램] → 넣기.
  - 학생은 학급 정보(`class-model getInfo()`의 학년·반)와 번호로 만들고 이름 칸은 비워 둠(선생님이 채움). 이미 같은 학년·반·번호 학생이 있으면 그 학생을 씀(겹쳐 넣지 않음).
  - 넣을 때 그 학생의 **사전 점수**를 적어 둠: 교과, 가장 낮은 영역(들), 점수율, 쓴 평가 id·이름, 날짜.
  - 넣은 뒤 「3명을 「○○」에 넣었어요 — 이름을 넣어 주세요」 + [기초학력으로 가기](학급 › 기초학력, 그 프로그램).
- 순수 함수(새 파일 `web/menus/evaluate/unit/unit-gap.js`): `gapStudents(tests, { cut })` → `[{ no, areas: [{ name, pct, tests: [id] }], worst, n }]`.

### 2-2. 사전·사후 점수 (학급 › 기초학력, `web/menus/class/camp*.js`)
- 저장: 프로그램에 `growth: { [studentId]: { subject, area, pre: { pct, tests: [{id, title}], date }, post: { pct, source: 'auto'|'manual', tests, date } | null } }` 더함(`normCamp`가 읽고 고침, 없으면 `{}`).
- 화면: 「결과 보고서」 단계 위(또는 「관찰 기록」 다음)에 카드 **「사전·사후 점수」** — 학생 | 교과·영역 | 사전 | 사후 | 변화(+n점, 오르면 ▲·내리면 ▼ 글자도).
  - 사후 **자동**: 그 프로그램의 첫 수업 날(없으면 학생을 넣은 날) 뒤에 본 같은 교과 단원평가에서 같은 영역 점수율(그 학생 번호). 여러 개면 가장 최근 것. 「자동 · ○○ 평가」로 표시.
  - **직접 입력**: 사전·사후 칸 모두 숫자로 고칠 수 있음(직접 고치면 source 'manual', 자동이 덮지 않음). 교과·영역도 글로 고칠 수 있음. 학생을 직접 넣었으면 빈 줄로 시작.
- 결과 보고서 AI(`reportPrompt`): `[사전·사후 점수]` 줄(학생A · 수학 수와 연산 45% → 78%(+33)) 더하고, 「운영 성과에 이 숫자를 그대로 쓰고 지어내지 말 것」 규칙.
- 결과 보고서 문서(`camp-docs.js` report): 성장 자료가 있으면 「사전·사후 성취」 표(학생 | 교과·영역 | 사전 | 사후 | 변화)를 끝에 넣음(문서는 이 기기에서 만들므로 이름 그대로).
- 단계 상태·문서 준비는 그대로(이 카드는 선택).

## 5. 근거가 보이는 평어

### 공통 모듈 `web/core/evidence.js` (순수 + 작은 화면 도우미)
- `evidenceList(items)` → `[{ id: 'e1', kind: 'unit'|'activity'|'gr'|'ref'|'memo', label, ai? }]` (학생마다 12개까지, label 300자까지, 같은 글은 하나). `ai`가 있으면 AI에는 그 글을 보냄(화면은 label).
- `evidencePrompt(list)` → 「[근거 목록]\ne1) 「3학년 수학 3단원」 덧셈 문항 — 잘함\n…」 한 학생 몫(`ai || label`).
- `EVIDENCE_RULE` → 「근거 목록에 있는 사실만 쓰고, 문장마다 기대는 근거 번호를 src에 적어요. 근거가 없는 문장은 src를 비워요(지어내지 않음).」
- `normSentences(v, list)` → `[{ t, src: [유효한 id] }]` (빈 문장 빼고, 목록에 없는 id 빼고). `joinSentences(ss)` → 평어 글.
- `evidenceHTML({ sentences, list, text })` → 문장마다 `근거 n` 단추(누르면 그 근거 줄이 펼쳐짐, `aria-expanded`), src가 빈 문장은 주황 **「근거 없음」**(글자도 함께). 지금 글(`text`)이 `joinSentences(sentences)`와 다르면 위에 「고친 글 · 근거는 처음 쓴 글 기준이에요」.
- 저장: 평어 옆에 `ev: { list, sentences }`. 근거가 없는 옛 평어는 표시 없이 지금처럼.

### 5-1. 단원평가 교과 평어 (`unit-results.js`·`unit-ai.js`)
- 근거: 그 학생의 평가 내용별 점수율(잘한 것 rate ≥ 0.8·보완할 것 < 0.6, 지금 `writePyeongeo`가 쓰는 것) → `kind: 'unit'`, 화면 「「3학년 수학 3단원」 세 자리 수 덧셈 90%」, AI에는 숫자 없이 「… — 잘함」「… — 보완 필요」(안내 글 「AI에는 번호·수준·평가 내용만 보내요」 그대로).
- `pyeongeoPrompt`에 학생마다 근거 목록 + `EVIDENCE_RULE`, 답 `{"students":[{"no":1,"sentences":[{"t":"…","src":["e1"]}]}]}`. `normPyeongeo`는 예전 `text` 답도 받음.
- 저장 `unit:pyeongeo:<교과>`의 `students[no].ev`. 화면 `pyHTML`: 고치는 칸(textarea) 아래 근거 표시.

### 5-2. 평가지 채점 평어 (`evaluate.js` mode 'gr')
- 근거: 채점 때 받은 `evidence[]`(답안 근거) → `gr`, `strengths`·`improve` → `gr`, 단원평가·활동지 참고 줄(`grRefLine`) → `ref`.
- `grWritePrompt` 답 `[{"no":N,"sentences":[{"t":"…","src":["e1"]}]}]`(예전 `text` 답도 받음). 한 학생 한 문장 규칙은 그대로.
- 저장 `ssam:gr:<id>` 학생마다 `ev`. 화면 `renderGRResults` 학생 줄 평어 아래 근거 표시. [전체복사]·표로 복사는 글만.

### 5-3. 행동특성 (`evaluate.js` mode 'hk')
- 근거: 교사 메모를 줄·쉼표로 나눈 조각(이름 칸 뺀 `memoForAI` 결과, 날짜 「[11. 6.]」 앞머리 그대로) → `memo`, 「m1) [11. 6.] 토론에서 근거를 들어 반론함」. 40조각까지(넘으면 최근 조각).
- 규칙은 `MEMO_RULE`(「메모를 바탕으로 쓰고(메모에 없는 사실은 쓰지 않음), 문장마다 기댄 메모 조각 번호를 src에…」) — 메모를 학교생활 모습으로 풀어 쓰는 글이라 「목록에 있는 사실만」으로 좁히지 않음.
- `hkPrompt`·`hkFixPrompt`(조금 길게/짧게) 답을 JSON `{"results":[{"sentences":[{"t":"…","src":["m1"]}]}]}`로(후보 수만큼). 길이 맞추기·`hkTrim` 뒤에도 문장과 근거를 함께 둠(잘린 문장은 빠짐).
- 저장 `ssam:hk` 후보마다 `ev`. 화면 `renderHKEditor` 후보 글 아래 근거 표시. 고치기(textarea)로 고치면 「고친 글」.

## 시험
- 단위: `unit-gap`(영역 점수율·기준·영역 없는 평가·결석/채점 안 한 학생 빼기), camp growth(정규화·자동 사후·직접 입력 우선·보고서 줄·문서 표), `core/evidence`(목록·프롬프트·정리·잘못된 id·글 합치기·고친 글 판별), `unit-ai` 평어 프롬프트/정리(새·옛 답).
- 화면: 결과 모아 보기에서 미도달 학생 → [기초학력에 넣기] → 기초학력에 학생·사전 점수, 뒤 단원평가로 사후 자동, 직접 고치기, 보고서 AI 글에 숫자(이름 없음) / 평어 3곳에서 근거 단추 펼치기·「근거 없음」·고친 글·복사는 글만.
