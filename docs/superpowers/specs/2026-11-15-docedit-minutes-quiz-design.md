# 쌤비서 새 기능 3가지: 문서 다듬기·새 서식으로 바꾸기 / 회의록 / 문항·활동지 만들기 (2026-11-15)

## 왜

충남교육청 「마주온 톡톡 2.0」(엘리스 헬피챗)이 교원에게 열렸다. 범용 AI 대화창이라 무엇이든 묻고 hwp를 올려 대화로 고칠 수 있다.
쌤비서는 범용 대화로 겨루지 않고, 그중 쌤비서 방식(학교 양식 그대로·이름 가리기·업무 흐름을 끝까지)으로 가져올 만한 세 가지를 넣는다.
선생님이 고른 세 가지를 모두 만들고, 차례는 1 → 2 → 3이다. 방식은 선생님이 「추천대로」 정했다.

1. **한글 문서 넣고 말로 다듬기** + 계획서 **새 서식으로 바꾸기**: 톡톡의 「hwp 올려 대화로 고치기」를 학교 양식(글꼴·문단·결재란)을 지키며.
2. **회의록 정리**: 쌤비서에 없는 업무. 협의회 메모 → 안건·협의·결정·할 일 → 학교 양식, 할 일은 「오늘」 화면에.
3. **문항·활동지 만들기 → 채점까지**: 만들기만이면 톡톡과 같다. 만든 문항이 그대로 단원평가 정답지·활동지 기준이 되어 스캔만 넣으면 채점되는 고리가 쌤비서 몫.

## 지켜야 할 것 (모든 기능)

- 학생 이름은 AI로 보내지 않는다. 교직원 이름·전화번호·이메일은 가려 보내고, 돌아온 글에는 원래 이름을 되돌려 넣는다. 주민번호·계좌·명단 줄은 보내지 않는다.
- 원본 파일은 저장하지 않는다(필요한 동안 메모리에만). 학교 양식으로 저장하는 것은 선생님이 넣은 .hwpx 양식만(기존 양식 저장소).
- 「AI로 가는 것」 안내(aiNoteHTML)에 무엇을 보내는지 적는다.
- 화면 말투: 해요체, 쉬운 말, 기존 화면과 같은 부품(m-page·카드·「화면 설명」·AI 줄). 휴대폰(390·360px)에서 겹치거나 가로로 넘치지 않는다.
- 학급 메뉴(학급 › 오늘 수업·진도표 등)와 연수 메뉴 화면은 고치지 않는다(다른 선생님이 맡음). 진도표 자료는 읽기만(class-model listSubjects).
- 시험: 기능마다 단위 시험(규칙) + 화면 시험(e2e). 고치기 전에 실패하는 시험부터. 지어낸 이름만(김하늘·이바다·한가람·새싹초등학교).
- 새 AI 업무 `doc`(「문서 다듬기·회의록」)을 core/ai-roles.js TASKS에 더하고 shell TASK_MENU에서 'etc'로. 문항 만들기는 `plan`(이름을 「계획 초안·문항 만들기」로).

## 공통 도우미: 가렸다 되돌리기 (core/redact.js)

letter-translate.js의 `guard`를 일반화. `redact(text) → { text, back(t) }`:
- 전화번호·이메일 → `{{n}}`, 교직원·학생 이름(core/privacy.js maskStaff·maskJosaNames·cleanSheet 이름 규칙) → 번호 붙은 자리 표시 `〔이름n〕`.
- `back`은 돌아온 글의 자리 표시를 원래 값으로. AI가 자리 표시를 지우면 그 값은 넣지 않는다(끝에 붙이지 않음 — 번역과 다름).
- 명단·주민번호 줄이 있으면 그 줄은 보내지 않고 `{ text: …(그 줄 뺌), dropped: n }`.
- letter-translate는 지금 동작 그대로 둔다(바꾸지 않음). 1A·2가 이 도우미를 쓴다.

## 1A. 문서·소통 › 「문서 다듬기」 (새 탭 `docedit`)

**하는 일**: .hwpx를 넣고 「공문체로 다듬어 줘」처럼 말하면 문단·표 칸마다 글만 바꾸고 모양은 그대로 둔 .hwpx를 내려받는다.

**방식(가)**: 문단 단위 고치기. 기존 hwpx-form.js의 readForm(줄 = 문단·표 칸 문단)·setText를 쓴다.
- 넣기: .hwpx(주). .hwp·.docx·.pdf·.txt는 글만 읽어 쌤비서 기본 문서로 내려받고 「한글에서 .hwpx로 저장해 넣으면 모양 그대로예요」 안내.
- 보낼 글: 빈 줄·그림만 있는 줄은 빼고 `[줄번호] 글` 목록(redact). 한 번에 약 12,000자·250줄까지, 넘으면 앞에서부터 묶음으로 나눠 같은 요청을 차례로.
- AI 답(JSON): `{ changes: [{ id, op: 'replace'|'delete'|'after', text }], note }`. 없는 id·빈 replace는 버린다.
- 적용: replace → 그 문단 글만 바꿈(첫 글자 모양 유지). delete → 표 칸 밖은 문단을 지우고, 표 칸 안은 글만 비움(표 모양 유지). after → 그 문단을 본으로 복제해 바로 뒤에 새 문단.
- 미리 보기: 바뀐 줄만 「전 → 후」로 나란히(지운 줄·더한 줄 표시), 줄마다 [되돌리기], [모두 되돌리기]. 바뀌지 않은 줄은 접어 둠.
- 여러 번 말하기: 바뀐 결과 위에 이어서 고침, [한 단계 되돌리기](최근 10단계).
- 빠른 요청 칩: 공문체로 · 짧게(절반쯤) · 맞춤법·띄어쓰기 · 쉬운 말로(학부모용) · 날짜·학년도 바꾸기(「2026학년도 → 2027학년도」처럼 묻고 바꿈은 AI 없이 글 바꾸기로) · 번호 꼴 맞추기.
- 내려받기: [한글로 내려받기](원래 파일 이름 + 「(다듬음)」). AI 줄은 업무 `doc`.
- 채팅·떠 있는 버튼: 「이 문서 공문체로 다듬어 줘」 + 파일 → 문서 다듬기 탭에 넣고 그 요청으로 시작(builder: 채팅 의도 사전에 「다듬어」「고쳐 줘」 + 한글 파일).

## 1B. 계획서 「새 서식으로 바꾸기」 + 작년 계획서 서식 함께 저장

**방식(나)**: 제목·본문 자리만 남기고 본문을 새로 채운다(기존 학교 양식 채우기 exportToForm/fillForm 그대로).

- **작년 계획서를 .hwpx로 넣으면 서식도 저장**: 연간계획 1단계 작년 계획서, 행사계획 참고 자료 「작년·기존 계획서」, 학급운영계획 작년 계획서가 .hwpx면 그 파일을 학교 양식 「작년 계획서 서식 · 파일이름」으로 저장하고(form-store, 같은 이름이면 바꿈), 그 계획서 종류에 고른 양식이 없으면 골라 둔다. 알림 한 줄. .hwp·PDF면 「한글에서 .hwpx로 저장해 넣으면 모양까지 따라가요」.
- **[새 서식으로 바꾸기]**: 연간·행사·학급운영계획의 내려받기 줄(formSlotHTML 옆). .hwpx 서식을 넣으면:
  1. 서식 글에서 큰 제목(parseOutline 1단계)을 읽음. 셋보다 적으면 「큰 제목을 찾지 못해 양식으로만 저장했어요」.
  2. 지금 초안의 칸(연간: outline 항목 key·title·글 / 행사: 계획서 글의 큰 제목 칸 / 학급운영: outline 칸)을 새 큰 제목에 맞춤: 먼저 규칙(같은 역할 roleOf·year-model ROLE, 제목 비슷함), 남은 것은 AI(업무 `plan`) — 옛 칸 제목·글(redact)과 새 제목들을 주고 `{ map: [{ to, from: [옛 칸 id] }], write: [{ to, text }] }`.
  3. 미리 보기: 새 제목마다 「← 옛 칸 이름」 / 「AI가 새로 씀」, 옮길 곳 없는 옛 칸은 「옮길 곳 없음」 + [이 칸에 붙이기] 고르기.
  4. [이대로 바꾸기] → 초안을 새 차례로 바꾸고(연간: outline·글, 행사: 계획서 글, 학급운영: outline·칸 글), 그 서식을 학교 양식으로 저장해 골라 둠. [되돌리기](한 단계)로 바꾸기 전 초안.
- 연간계획의 지침 점검·작년 비교는 새 차례(textKeys)로 그대로 돈다.

## 2. 문서·소통 › 「회의록」 (새 탭 `minutes`)

- **넣기**: 메모를 붙여 넣거나(주) 파일(hwpx·hwp·docx·pdf·txt 글). 판서·메모 사진은 AI가 있을 때 그림 그대로 보냄(쪽지처럼 그렇다고 알림).
- **칸**: 회의 종류(학년 협의회·교과 협의회·부서 협의회·학교운영위원회·기타) · 회의 이름 · 일시(날짜·시간) · 장소 · 참석(직함·인원, 이름은 이 기기에만).
- **AI(업무 `doc`, redact)** → `{ title, date, time, place, attendees, agenda: [{ title, discussion: [], decisions: [] }], todos: [{ task, who, due }], next: { date, topic } }`. 개조식(~함·~임), 메모에 없는 결정·숫자는 지어내지 않음. 연도 없는 날은 학년도 규칙(쪽지·공문 처리와 같게).
- **고치기**: 칸·안건 카드(협의 내용·결정 사항 줄 더하기·빼기)·할 일 표(체크·담당·기한). 선생님이 고친 칸은 다시 정리해도 그대로(쪽지 keepFields처럼).
- **내보내기**: [복사](개조식 글), 쌤비서 기본 회의록 문서(한글·워드·PDF — 기존 문서 내보내기), 학교 양식(.hwpx: formSlotHTML·registerFormDoc 'minutes' — 제목·본문·날짜 자리).
- **할 일 → 「오늘」**: 끝내지 않은 할 일 가운데 기한이 7일 안(지남 포함)인 것을 「오늘」 화면 기한 카드와 채팅 「오늘 할 일」에 「회의 할 일」로(공문 기한과 같은 모양), 누르면 그 회의록.
- **최근 회의록**: 20개, [열기]·[삭제](묻고).
- 채팅: 「회의록 정리해 줘」 + 글 → 회의록 탭에 넣고 바로 정리.

## 3. 문항·활동지 만들기 → 채점까지

**들어가는 곳**: 평가 › 단원평가 목록 [문항 만들기], 평가 › 활동지 목록 [활동지 만들기]. (학급 화면에는 두지 않음)

- **고르기**: 교과(진도표 교과, 없으면 직접) → 차시(기본: 진도표에서 오늘 다음 차시, 단원 전체·여러 차시 고르기) — 진도표가 없으면 「단원·성취기준·범위」 글 칸. 문항 수(기본 5, 3~20), 유형(객관식·단답·서술형 섞기), 수준(기본·보통·도전).
- **AI(업무 `plan`)**: 학생 자료는 보내지 않음. 단원평가 → `items: [{ no, type: 'choice'|'short'|'essay', question, choices[], answer, points, content, domain, criteria, pages }]`. 앱이 확인: 객관식 정답은 보기 번호 안, 배점은 합 100(문항 수로 나누고 서술형은 두 배 비율 — 선생님이 고칠 수 있음).
- **고치기**: 문항 카드(물음·보기·정답·배점·평가 내용·서술형 채점 기준), [이 문항 다시 만들기], [문항 더하기], [빼기].
- **[평가 만들기]**: unit-model newTest로 새 단원평가(meta: 교과·학년·단원·차시 이름, key.items = 문항(번호·정답·배점·평가 내용·영역·유형·채점 기준·쪽), paper.text = 문제지 글)를 만들고 그 평가를 엶 → 1단계 「답안」이 이미 채워진 상태. 학생 문제지 스캔만 넣으면 지금처럼 채점.
- **[문제지 내려받기]**: 학생 문제지(위에 「학년 반 번호 이름」 칸, 제목, 문항·①~⑤ 보기, 단답·서술형 답 칸)와 정답지를 한글·워드·PDF로(기존 문서 내보내기). 번호 칸 위치는 늘 같게(적힌 번호로 학생 맞추기·이름 칸 가리기가 쉽게).
- **활동지**: [활동지 만들기] → 열린 문항(쓰기·그리기·생각 정리) + 문항마다 ○·△ 기준 → activity-model로 새 활동지(문항·기준 확정 상태, sheet.student = 활동지 글)를 만들고 엶. 학생 활동지 내려받기.

## 방식 비교 (정한 것)

- 문서 다듬기: (가) 문단 단위 고치기 ← 고름. 모양이 가장 잘 지켜짐. (나) 본문 다시 쓰기는 표·글자 꾸밈이 사라져 다듬기엔 맞지 않음. (다) 쌤비서 문서로 다시 만들기는 학교 모양을 잃음.
- 새 서식으로 바꾸기: (나) 본문 다시 채우기 ← 고름. 차례가 바뀌므로 문단 단위로는 못 함. 기존 학교 양식 채우기를 그대로 씀.
- 회의록: 쪽지·결과 보고와 같은 「넣기 → AI 칸 → 고치기 → 내보내기」 꼴 ← 고름(새 틀을 만들지 않음). 녹음 받아쓰기는 하지 않음(받아쓴 글을 붙여 넣으면 됨).
- 문항 만들기: 만든 문항을 단원평가·활동지 자료로 바로 만듦 ← 고름. 따로 「문항 은행」을 두지 않음(YAGNI).

## 하지 않는 것

- 범용 대화(무엇이든 묻기)·교육청 규정 에이전트·녹음 받아쓰기·문항 은행·학생용 AI.
- 문서 다듬기에서 새 표 만들기·차례 크게 바꾸기(그건 새 서식으로 바꾸기·직접 고치기).
- 학급·연수 화면 고치기.

## builder가 정할 것

- 탭 차례(문서·소통: 쪽지 작성 · 가정통신문 · 공문 처리 · 회의록 · 문서 다듬기 · 인수인계서 · 다면평가 권장), 저장 키 이름, 빠른 칩의 정확한 문구, 미리 보기 모양, 묶음 크기 세부, 문제지 쪽 모양.
